# Observer 需求基线

更新：2026-09-05。状态：Q1–Q75 及整体共享理解均已由 Owner 确认；已汇总为 [PRD](PRD.md)，尚未进入实现。

本文件汇总当前会话的有效决策。后续用户修改覆盖先前答案；研究报告中的建议、示例参数和旧的四/五栏目描述不自动成为产品要求。领域语言见 [CONTEXT.md](../CONTEXT.md)，架构理由见 [ADR](adr/)。

## 1. 产品目标与范围

Observer 是单用户、私人使用的每日信息简报服务。它利用 Codex、Claude 等 coding agent 的研究和编辑能力，帮助 Owner 理解世界范围内的重要变化，并保留可追溯证据。

- 日报全年每日生成，简体中文成稿，支持多语言来源。
- 常规覆盖中国、美国、欧盟；其他地区纳入全球性或重大区域事件。覆盖缺口必须披露。
- 不约束整期阅读时长。每个 Edition 约 7 条，其中约 3 条重点、4 条速览；质量不足允许少于目标数量。
- Today Overview 汇总六个 Edition 的首要事件与缺口，作为导航。
- V1 不设业务成本预算上限，但记录消耗，限制任务时长、轮数、重试和异常调用，避免失控。
- 私人部署、无公众注册、无多租户、无公开新闻门户。

## 2. 六个 Edition

| Edition | 内容边界 |
|---|---|
| 世界要闻 | 地缘政治、战争外交、选举政策、灾害、公共卫生、气候、人道事件；地方猎奇与娱乐默认不收录 |
| AI 日报 | 模型、论文、评测、产品、开发工具、AI 基础设施、安全治理、版权与行业采用 |
| 财经日报 | 宏观、央行监管、财报、并购资本事件、供应冲击；许可明确时加入收盘市场背景 |
| 科技前沿 | 半导体计算、机器人、量子、航天、生物科技、能源材料、网络安全及新型基础设施 |
| 社交话语观察 | 与其他故事关联的讨论，以及符合采样门槛的平台原生新兴话题 |
| GitHub 热门项目 | Observer 根据官方元数据计算的关注度动量与新颖性，包含历史报道降权 |

同一事件组成 Event Cluster，指定主 Edition 展开。其他 Edition 通过 Impact Note 交叉引用，不计入常规条数。只有独立的新事实或不同分析对象才拆成独立故事。

财经不提供买卖信号、目标价、收益承诺、持仓分析或实时行情。GitHub 热度不等于代码质量、安全性或安装推荐。

## 3. 每日出版契约

- 持久化时间使用 UTC；业务日期和调度明确采用 Asia/Shanghai。
- 全天持续采集，最近 24 小时是常规覆盖窗口；每日 07:30 冻结 Evidence Bundle。
- 入选依据是本期首次公开披露或发生实质新进展；分别保存事件时间、发布时间和首次发现时间。系统漏采旧闻只在仍有重大价值时标明“补报”；旧事件无新进展不重复报道。
- 截稿后允许补充证据纠正当期候选的重大错误，不纳入普通新事件；后者进入下一期。
- 08:30 硬验收点是私有服务端报告可读取。邮件分别记录服务商受理、投递和退信，不能将受理当成收件箱可见。
- 栏目失败独立重试；已完成内容准时发布，缺失明确标注。
- 节点恢复且能在当日 12:00 前完成时可发布 Delayed Brief；超过恢复窗口记录 Missed Brief，不回填为准时发布。
- 延迟与内容降级是两个维度，同一份报告可同时标记。
- Agent 全部不可用但采集有效时，只发布来源政策允许的标题、来源、时间和链接，不生成分析或伪造摘要。
- 采集与 Agent 均无法提供可信内容时记录缺刊。
- 已发布日报的缺失栏目在当日 12:00 前恢复时，可补齐为新版本；之后不补刊。补齐仍受原刊时间窗口约束，普通新进展进入下一期。
- 每次日更生成前复查最近 7 天已报道故事的来源更正、撤回和重大冲突。可靠更正证据触发重新核验和新版本；无法解决的重大错误先撤回相关条目，重大事实更正重新发邮件。
- 12:00 是缺刊恢复与缺失栏目补齐的截止时间，不是停止纠错或撤回的期限。

## 4. 证据与编辑规则

普通事实需要一个适当的一手来源或两个独立可靠来源。公司、政府或其他发布者的声明只能证明其作出了该声明，不能自动证明声明中的效果或判断为真。

战争、冲突、伤亡、选举与重大财经事实适用更严格交叉验证。世界要闻的高风险项目至少使用两个独立可靠来源，尽量纳入官方或现场一手材料；单方面说法显式归因，数字附统计时间，冲突数字展示区间和分歧。不使用未经核验的社交视频或血腥图片。

- 来源类型包含一手、独立媒体/研究、专家社区、社交样本；预印本额外标明未经同行评审。这些标签可以组合，不强制互斥。
- 可信状态使用高/中/待确认等可解释标签，不展示未经校准的概率。
- 专家或社交观点不能替代事实证据。未确认内容独立标记，不占正式条数，不能绕过高风险门槛。
- 正文允许影响路径、情景推演和竞争解释，但必须与事实分开，不使用煽动性标题。
- 重点故事结构：一句话结论、事件、重要性、影响路径、争议/反证/未知、来源。
- 重点条目软目标约 400–800 中文字，复杂事件最多约 1200 字；速览约 100–250 字。不为满足字数填充内容。
- 外文正式名称首次出现保留原名；来源标题保留原文，可附中文意译；译文与直接引语准确标识。
- 每条故事就近列来源名称、标题、发布时间、访问时间、直达链接；关键陈述在 Report Record 中关联 evidence_id，PDF 保留链接。

## 5. 来源与个性化

Source Registry 保存已审阅的来源。Source Policy 在采集、模型处理、存储和分发各阶段约束允许字段与用途。未知来源可以作为发现线索；Agent 只能提出 Source Proposal，不能自行批准它成为发布依据。

来源与兴趣均通过配置文件维护。Agent 将来源建议写入待审清单，由 Owner 通过配置变更启用；日常生产在已批准来源上全自动运行，无需每天审批，也不提供管理后台。

- 成品采用原创短摘要、必要短引文、出处时间和链接；默认不复制图片、全文、付费墙内容或绕过访问控制。
- 新闻发现可用聚合索引与 RSS，事实尽量回到原始发布；具体首发清单须逐源核查。
- 财经优先监管与统计机构等一手资料；FRED 与未经许可实时行情默认不接入，具体条款以接入时复核为准。
- X/Reddit 等许可未明确来源不进入 Agent 或不可撤回导出物。没有合规样本时社交栏目标明覆盖不足。
- 社交观察披露平台、语言、地区依据、查询、时间、样本量与缺口；不声称总体民意，不做跨平台身份画像。
- Interest Profile 通过配置文件维护关注实体、地区、主题、权重与排除项；支持版本化导入导出。
- Global Baseline 保留重大事件的入选资格；不采集阅读时长，不隐式学习或静默改写兴趣。

## 6. Agent 工作流与权限

确定性采集器 → 来源政策校验与 Evidence Bundle → 六个 Edition Research Agent → 内容/证据校验 → Final Editor → 发布校验 → Canonical Markdown → PDF/邮件 HTML/客户端呈现。

- V1 通过统一 AgentRunner 管理 `codex exec` 与 `claude -p` 子进程，采用结构化输出、独立工作目录、终态检查、超时和日志隔离。可替换为 SDK。
- 一次任务使用一个主 Agent。另一个用于低置信度、高影响、来源冲突复核、故障替代和周期对照。
- 六个 Edition 分工、独立失败重试；分工不等于无限并发，并发上限经实测确定。
- Research Agent 只读材料，可用受控检索、网页读取和只读 MCP；Final Editor 只读已校验 Report Record，无 Web 或 shell，不能引入新事实。
- Agent 不执行候选源码、不下载二进制、不修改服务配置、不发邮件。
- 各类工具和出网通道分别约束。不能假设 shell 网络代理同时限制内建搜索或 MCP。
- 程序校验负责结构、时间、引用标识、策略等；陈述是否受原文支持仍需证据核验与质量评测，JSON Schema 本身不能证明事实真实。

## 7. 内容底稿、版本与交付

Report Record 是机器事实与审计底稿；Canonical Markdown 是唯一人类可读发布底稿。PDF 从 Markdown 转换，邮件 HTML 和客户端内容从同版本 Markdown 派生。各渠道不得分别由 Agent 重新撰写。

- V1：服务端生成、私有归档、邮件、MD/PDF 下载和稳定同步 API。
- 邮件用固定 HTML 模板展示 Today Overview 与私有签名链接；附件符合预算时可附 PDF，否则下载。HTTPS 邮件 API 优先，具体供应商待选。
- Phase 2：Android 客户端，覆盖无 GMS 手机；用户主动打开或刷新时同步，无推送、无后台及时通知承诺。
- 客户端通过一次性配对码绑定，后续使用可撤销凭证。所有报告和接口默认私有。
- Android 支持日期/Edition 浏览、版本与更正记录、重新下载；全文搜索后置。
- 无人工编辑器、无结构化人工 override 功能。更正通过有证据的重新生成产生新 Report Version，旧版标记 superseded 或 retracted，不静默覆盖。
- 权利删除要求优先于对终端长期提供原文副本；可保留允许的版本元数据与撤回说明。

## 8. GitHub 热度与重复衰减

使用官方 API 元数据建立 Observer 热度，不镜像官方 Trending。候选不限制编程语言，按 Interest Profile 加权主题；比较动量时考虑语言、仓库年龄 cohort，避免仅按累计 stars 排序。

- 过滤非公开、不可访问、archived、disabled、fork、mirror、template 仓库；风险不清楚项目自动隔离。
- 以稳定 repository node ID 关联报道历史，改名转移不重置记录。
- 每小时采集累计 stars/forks 快照；24h 净增为两个快照差，可为负，显示实际时间。
- 截止点快照容忍 ±15 分钟、历史快照容忍 ±60 分钟；没有完整比较窗口时单独显示 Cold-start Heat，不能混入正式 24h 动量榜。
- 报道后 7 天普通入榜冷却，随后在 30 天内线性恢复，近 90 天报道频率继续惩罚。
- 每期至少一半位置面向过去 30 天未报道项目。该规则与质量门槛冲突时不以低质量内容补位。
- 重大稳定 Release、明确关联的高危/严重安全事件、极端再次增长可一次性绕过冷却；事件 ID/修订去重，展示重新入榜原因。
- 安全事件呈现为风险更新，不当作安装推荐；普通更新不重复升权。
- 搜索分片不完整、限额或快照缺失时显式降级，不凑满 7 条，不把无法可靠计算的数据放入正式排名。
- V1 采用限期、最小只读权限 fine-grained PAT，服务端保管；不进入 Agent Prompt、APK 或配置仓库。
- 小时快照 90 天后压缩为每日快照；报道历史、事件去重标识和评分版本长期保存。

具体热度权重、极端分位、cohort 最小样本、频率惩罚函数仍是规格/回放评测参数；研究报告的示例公式未被自动采纳为最终算法。归档需保留已发布排名实际使用的两个快照或充分计算证据，避免压缩后无法核对已发布数字。

## 9. 部署与恢复

V1 为云厂商中立的单节点 Linux VPS，新加坡优先、东京备选；实际供应商与账户资格按启用时核查。VPN 可用于安全管理，不用来伪装 Agent 出口地域。未满足启用条件的 Runner 保持禁用。

- 接受单点故障，不做自动故障转移或 Kubernetes；容器化运行。
- 公网服务使用 HTTPS、鉴权和可撤销设备凭证；密钥与内容分离。
- 恢复目标 RPO ≤ 24h、RTO ≤ 4h，属于待恢复演练验证的目标。
- 数据库一致性备份、配置与成品保存在节点外私有对象存储；日报发布后及时备份成品。
- COS 是已研究的可选实现；云厂商中立决策不强制购买腾讯云产品。
- 每季度至少进行一次实际恢复演练，检查报告、数据库索引与配置；节点快照不能替代一致性备份。
- 长期保存 Report Record、Markdown、PDF、来源元数据与允许的证据哈希；原文按 Source Policy 缓存；社交删除信号触发清理；脱敏 Agent 日志 30 天。

## 10. 验证与移交边界

正式自动发布前进行连续 14 天同源影子评测，结果进入测试归档。人工核查全部重点故事及至少 20% 速览，验证引用支持、错误归因、无来源事实、漏报、重复、分类、中文表达、结构成功率、时延和费用。日常无人工编辑功能与上线前人工验收并不矛盾。

通过要求：零伪造来源、零严重事实错误；抽查事实有证据支持的比例 ≥98%；所有发布候选通过结构与来源政策校验；14 天中至少 13 天在 08:30 前形成可读取报告。这些是已采纳的项目准入标准，不是已取得的结果或供应商承诺。

仅一个 Provider 可用时可以验收其单独运行能力，不声称完成双 Provider 对照或故障切换验证。两者均不可用时，链接降级版只能验证采集和交付，不能证明 Agent 内容能力通过。服务可用、邮件受理、实际投递、内容正确性、恢复成功必须分别取证。

以下留到规格阶段明确，不能在实现时静默猜测：

1. 首发来源清单及可用范围、社交最小样本和隔离标准；Interest Profile 初始配置。
2. 将已确认的首次披露、新进展、补报及截稿规则转化为时间字段、判定契约和边界用例。
3. 热度评分系数、快照调度相位、缺样处理、冷启动展示、新颖性配额与事件升权的精确优先级。
4. 内容校验失败与 Agent 失败的分类、复核仲裁接口，以及自动更正、撤回、补齐和缺刊的状态转换实现。
5. 将已确认评测阈值转化为核查表、事实计数规则、严重错误判定例子及可追溯的评测记录。
6. 邮件重试与更正版去重、签名链接有效期、附件预算、设备凭证寿命及撤销；恢复计时起点。
7. 实现语言、数据库、对象存储和邮件供应商、确切 CLI/模型版本、运行并发与资源规格。

这些是明确的后续设计工作；本文不将它们伪装成已实现或已验收。付费调用、资源采购、部署、开发和 Android 制作尚未执行。

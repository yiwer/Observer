## What to build

Owner 通过审阅过的来源配置接入一个 RSS/Atom 来源，从持续采集到可供研究使用的 Evidence Bundle 全程执行 Source Policy，并能看见来源缺口与待审 Source Proposal。

## Acceptance criteria

- [ ] 来源配置明确身份、审阅状态、允许字段、模型处理、存储期限、引用、分发及删除规则；未批准来源只能进入待审提案，Agent 不能自行启用。
- [ ] 采集保存允许的原始发布时间、首次发现/获取时间、事件时间（可未知）、直达链接、来源类型和允许的证据或哈希；多语言文本不被默认过滤，未知时间不补造。
- [ ] RSS/Atom 增量重采、重复记录、无变化、网络超时与速率限制有可观察结果；单源故障形成 Coverage Gap，不解释为该地区没有新闻。
- [ ] 分别验证禁止采集、禁止存储、禁止模型处理和禁止分发的策略；后续阶段读取的是对应许可范围内的材料，不通过 Prompt 代替权限门。
- [ ] 正文读取采用受控网络边界，测试恶意重定向、内网/本机目标、异常响应体与不可信网页指令；有效来源仍可形成可用 Bundle。
- [ ] 首个演示来源使用许可清楚的测试数据；真实首发源逐项留下政策审阅记录和启用条件，不默认启用 FRED、未授权行情或社交源。

## Scope boundary

先完成一个通用订阅来源闭环；GitHub 与社交专用协议留给对应票，来源法律许可不由连接成功代替。

## Decisions and evidence

在此确定来源配置与审阅记录的技术格式、采集限额和合理缓存默认值，交付版本化的示例配置。

验收交接需区分固定数据/替身、真实外部接入和人工检查；结果绑定实际代码及配置版本，缺少证据的类别标为未验证。

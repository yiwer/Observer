## What to build

到期数据和来源要求删除的内容会从模型材料、归档及导出访问路径中清理，同时保留许可允许的版本墓碑和已发布 GitHub 计算依据。

## Acceptance criteria

- [ ] 原文/社交材料按各自 Source Policy 清理，脱敏 Agent 事件日志保留 30 天；长期保留的 Report Record、MD/PDF 和元数据仍服从来源权利例外。
- [ ] 来源许可收紧或删除要求可以阻断受影响读取并清理关联正文/派生产物，保留允许的 tombstone 审计；这属于权限删除，不伪装成普通静默编辑。
- [ ] 无法撤回的已送邮件/附件不承诺远程删除：发送前必须已满足分发许可，后续记录不可撤回范围并阻止继续分发。
- [ ] GitHub 小时快照 90 天后压缩为每日快照，但已发布数字和排序所需输入继续保留，仓库报道历史及事件去重身份保持连续。
- [ ] 清理可重入、可恢复且输出删除/保留原因；日志、Prompt 和普通备份内容不包含秘密。
- [ ] 以时间推进、许可变化、关联版本和已发表榜单回放验证清理及重算；输出供备份票执行的删除标记/清理契约，防止恢复旧备份复活已禁内容。

## Scope boundary

存活系统内的保留与删除闭环，以及备份必须遵循的删除契约；备份落地/恢复由专门票完成。

## Decisions and evidence

明确权利删除优先于不可变正文和长期审计的边界，只保留许可允许的数据。

验收交接需区分固定数据/替身、真实外部接入和人工检查；结果绑定实际代码及配置版本，缺少证据的类别标为未验证。

规划 ID：V1-25 · 类型：implementation

## What to build

同一 Evidence Bundle 的 Provider 输出进入独立测试归档，形成可供人工核查的陈述级表单、抽样记录及质量/准时统计，为 14 天真实评测准备可持续运行的工具。

## Acceptance criteria

- [ ] 评测和日常出版空间隔离；同日对比使用同一冻结 Evidence Bundle、配置和固定评测规则，保留 Provider/模型/CLI、代码版本及输入指纹。
- [ ] 核查表覆盖全部 Priority Story 及至少 20% Watch Item，保存抽样方法、抽样集合、每个事实陈述、对应证据和人工判定；空样本不能记 100% 支持。
- [ ] 统计伪造来源、严重事实错误、事实支持比例、遗漏/重复/分类、表达、失败、耗时和可获得成本；分母是核查事实，不是可打开链接数。
- [ ] 分别统计正常准时、降级准时、延迟和缺刊，保存实际服务端可读时间；受理邮件或替身通过不能替代准时/内容证据。
- [ ] 预先形成严重错误例子、事实切分、样本计算、比较口径及缺失数据规则，交由实测启动前核定并冻结。
- [ ] 固定造假、错误归因、重复、无事实、缺失人工核查和单 Provider 样本能得到预期统计；两者均不可用的链接版不产生模型质量 PASS。
- [ ] 支持日常任务持久记录、失败续采和按冻结批次导出，方便长期运行跨多个 agent 上下文；本票不以 14 天完成为开发验收条件。

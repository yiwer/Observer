## What to build

给定可靠更正或重大未解错误信号，系统自动核验并创建 Correction/撤回关系，Owner 看到新旧版本状态，重大事实更正触发幂等邮件。

## Acceptance criteria

- [ ] 更正材料记录获取时间、用途和受影响陈述，经过与正常报道兼容的证据门；即使过 12:00 仍可处理，不回写原 Evidence Bundle。
- [ ] 可靠更正生成新 Report Version 并说明变化与证据；重大无法解决错误先撤回相关内容，保留清楚的状态说明。
- [ ] 既有正文不静默覆盖，归档/同步/下载可识别 superseded 或 retracted；当前入口不会把撤回陈述继续当有效事实。
- [ ] 重大事实更正通知使用既有邮件幂等身份，重复输入或重启不重复已完成通知；普通新进展进入下一期，非更正理由。
- [ ] 同一原版本出现补齐、更正或撤回竞争时有确定串行/冲突规则，不丢失已接受更正，也不恢复已撤回错误。
- [ ] 从固定更正输入验证至新 MD/PDF、归档版本关系和邮件状态；正午前后、重复更正、相互冲突和错误解除都有用例。

## Scope boundary

更正/撤回的生产处理，不提供人工编辑界面；自动发现最近报道变动在下一票。

## Decisions and evidence

固定更正严重度、通知条件与版本并发规则，不允许人工绕过 Publication Gate。

验收交接需区分固定数据/替身、真实外部接入和人工检查；结果绑定实际代码及配置版本，缺少证据的类别标为未验证。

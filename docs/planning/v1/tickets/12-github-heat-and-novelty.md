## What to build

GitHub Edition 根据可解释的动量、新颖性与报道历史选出项目，让新项目和成熟项目新动量都有机会出现，并可重算已发布排序。

## Acceptance criteria

- [ ] 在语言/仓库年龄 cohort 内比较，主题按显式兴趣配置加权而不限制语言；累计 stars 不独自主导，冷启动展示和实测动量保持分区/标签。
- [ ] 报道后 7 天普通冷却，之后 30 天线性恢复并受近 90 天报道频率惩罚；改名/转移沿用原历史，重复运行未发布结果不写报道历史。
- [ ] 正常选择至少一半位置面向过去 30 天未报道项目；奇数位置如何取整、质量不足缩减、候选过少和小 cohort 回退均有确定规则及测试。
- [ ] 记录评分版本、函数、系数、cohort 定义、输入快照、排名和入选/落选理由；按出版时保存的输入能重算排序。
- [ ] 回放覆盖 7/30/90 天边界、频繁重复、负净增、冷启动与小样本；比较不同参数的偏差后冻结首版算法，不照抄研究示例常量。
- [ ] 发布说明明确热度衡量关注而非代码质量或安装安全；每次算法变化产生新版本，不篡改既有报告的评分依据。

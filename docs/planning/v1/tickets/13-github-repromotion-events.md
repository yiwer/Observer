## What to build

已经报道的项目在重大稳定 Release、安全事件或极端新动量出现时可以一次绕过普通降权，并在 Edition 中显示新进展及风险标签。

## Acceptance criteria

- [ ] 稳定 Release、明确关联的高危/严重安全事件与极端再次增长各有来源证据、事件身份及实质修订身份；普通小更新不满足绕过条件。
- [ ] 同一事件重复采集、重试、改名和重复编排不会再次消耗一次性绕过；只在成功出版后提交相应已报道历史。
- [ ] 首版精确极端分位/最小样本规则、事件修订边界及升权与新颖性配额冲突优先级有版本化决策和回放，不静默削弱 PRD 至少一半新颖位置的要求。
- [ ] 安全事件以风险更新呈现，说明影响范围与证据，不变成安装推荐；风险无法确认的仓库继续隔离。
- [ ] 同一数据可重算常规衰减、绕过及最终入选理由；数据不完整导致的限制在正文可见。
- [ ] 跨多期验证首次事件入榜、重放被抑制、实质新修订重新判定、低质量不凑数和配额冲突。

## Scope boundary

只扩展既有 GitHub 选择闭环，不执行项目代码，也不另建无证据的安全扫描器。

## Decisions and evidence

明确 7 条目标下的新颖性整数边界与事件竞争规则；若与已批准语义冲突，回到 Owner 决策而非自行变更。

验收交接需区分固定数据/替身、真实外部接入和人工检查；结果绑定实际代码及配置版本，缺少证据的类别标为未验证。

## What to build

将 Agent 候选逐条核验为可发布、待确认或隔离项，使 Owner 读到的事实、发布者声明和分析具有不同语义及就近证据，而不只是一份通过 JSON Schema 的文本。

## Acceptance criteria

- [ ] 每个重要事实陈述关联具体 Evidence；普通事实接受适当一手来源或两个独立可靠来源，同一上游稿件的转载不重复计为独立来源。
- [ ] 声明只支持发布者说过什么；分析标识为解释或情景，不提升为已证实事实；引语有原文核查依据，翻译引语明确标识。
- [ ] 结构检查、来源政策检查、语义支持判断分开记录；结构正确但证据无关、来源不存在、过期政策禁止分发的候选不得直接发布。
- [ ] 来源冲突与不足形成解释清楚的 Unconfirmed Item 或缺口；没有未经校准的精确置信度百分数，失败保留可追查理由。
- [ ] 正反例从候选输入一直验证至归档正文：正确事实通过，伪造引用、单方声明升级、转载伪独立和恶意材料均被正确处置。
- [ ] 语义核验接口保留输入证据、结论及理由，可接入真实 Research Agent/复核；本票替身与标注用例只能证明判定流程，真实事实质量在影子评测验收。

## Scope boundary

通用证据门；高风险财经/世界要闻及 AI/科技成熟度规则由专门票加严。

## Decisions and evidence

固定失败分类、核验结果和复核接口；不把模型判断包装成确定性事实证明。

验收交接需区分固定数据/替身、真实外部接入和人工检查；结果绑定实际代码及配置版本，缺少证据的类别标为未验证。

# V1-06 六栏与 Canonical Brief

范围：[GitHub #6](https://github.com/yiwer/Observer/issues/6)、[本地票](../planning/v1/tickets/06-six-edition-canonical-brief.md)。固定起点 `e57832f65222c949b00acb12bbb5196ae2c2c033`；实施分支 `ticket/v1-06`。遵循 PRD D1/D2/D7/D9、T1、AC-01/AC-15 与 ADR-0001/0004/0005。

## 同一个业务 seam

测试和调用者均通过 `createObserver(...).produce(input)` → `readReport(version.id, ownerToken)` 观察整期出版，使用真实 SQLite。新增输入版本 2 接收业务日期、配置、Evidence Bundle，以及恰好六个 `{ edition, evidenceIds }` 分配；不能传入 Report Record、Canonical Markdown 或自由成稿。

`ObserverOptions.editionRunner` 是整期研究结果的外部 Adapter，接收经过模型许可字段投影的 `SixEditionRequest`，返回 `EditionResearch` v2。它与已有单任务 `runner` 明确区分；本票用固定结果替身，不创建六个真实 CLI 进程，不实现 Provider 选择、复核、重试或调度。后续 #14 可实现该 Adapter。旧 `AgentRunner`、ProduceRequest v1 和 Codex/Claude 的候选/进程协议保持原契约。

整期结果携带 task/Bundle/configuration 身份以及六个不同 Edition。单栏完成结果的任务 ID 为 `${taskId}:${edition}`，Bundle/configuration 必须与整期一致，候选所属 Edition 和证据引用必须属于本栏分配。新的 EditionResearch v2 与 Record v3 单栏元数据（成功/失败均同样适用）显式容纳原始 200 字符 taskId 加冒号和最长固定栏目后缀，最大 220 字符；旧 AgentResult/CLI taskId 仍为 200 字符，其他身份边界不变。整期关联错误、重复/缺失 Edition、越界证据、来源准入/模型禁用/研究发送前过期等拒绝整期，不生成部分 SQLite 行。研究 Adapter 整体抛错也不能伪装成六个成功任务。

每栏状态分别保存：

- `no-evidence`：本栏证据集合为空，无 Agent 运行身份。整期证据全空时不调用研究 Adapter，生成六个明确缺口。
- `completed`：保留实际运行终态。成功可以返回零候选（只在新的整期结果契约中允许，旧 AgentResult v1 的非空约束未放宽）；失败/取消保留原 category、执行元数据和已取得的 nullable 用量。
- `invalid-output`：可识别所属 Edition，但该栏输出结构无效；丢弃无法信任的候选及元数据，不发明 Provider、模型或成功身份，其他有效栏继续。

成功无候选、候选未过门、单栏运行失败、空证据与既有来源缺口分别可见。来源缺口 reason 在新输入中使用固定原因码，禁止借自由文本 gap 输入未经核验的事实；旧 Bundle/归档仍沿用其历史契约。

## 选题与正文

所有候选陈述仍经过同一个 Publication Gate：结构、政策和语义判定分开，适当一手/独立来源、声明归因、解释/情景、引文与译文等旧规则保留。Gate 之后按研究结果给定的优先顺序，通常每栏取前 7 个可发布故事、其中前 3 个作重点。来源许可或质量不足时减少实际数量；没有低质量补位、字数下限或整期读时上限。更复杂的排序、跨天去重和主题规则由后续票追加。

Priority Story 分为事件、意义、影响路径、未知。事件引用已核验的非分析陈述；后三类引用已核验的 analysis Claim，保留 explanation/scenario 标签。缺少对应分析时显示内容缺口，不自动编造解释。Watch Item 直接保留已核验陈述。PRD 400–800 中文字、复杂约 1200 字、Watch 100–250 字是研究内容的软目标；呈现不会补写或截断证据以凑篇幅。已有 Claim 的 4000 字符输入安全边界不等于整篇阅读限额；带归因的 Record v3 标题为完整已核验 Claim 预留标签长度。

研究结果可给出 `editorial`，其中只有 story/Claim ID 和目标 Edition：`significanceClaimIds`、`impactClaimIds`、`uncertaintyClaimIds`、`impactNotes`。不能传入待注入段落。被隔离、未确认、悬空的 Claim，以及试图把普通 fact 包装成分析的引用不会进入这些位置；缺失引用记录明确缺口。Impact Note 只引用主故事已核验分析，链接本版本主栏全文，放在目标栏专用位置，不进入普通 storyIds 或重点配额。本票不识别 Event Cluster，也不判断跨天去重。

Final Editor 是 `sixEditionMarkdown` 的确定性投影，只接收已经过 schema 与 Gate 关系检查的 Report Record。它不接收候选原文、研究 Adapter、Verifier、网络、shell 或任意编辑回调。标题从已核验事实生成；没有事实时用带类型/归因的声明或分析，纯引语不重复原文作标题。所有正文引用和数字均来自 Record 中的已核验 Claim。待确认内容留在对应 Edition，保持“非已证事实”及支持/相反来源归因，不进入总览标题。

Today Overview 按固定六栏顺序引用各栏首个入选标题与本栏缺口，使用同版本锚点。每栏只有一个二级标题，隔离项归属依靠保存的 candidateStoryIds，不依赖故事 ID 的命名格式。元数据与正文文本经过 Markdown 转义，证据 URL 使用链接目标编码；来源标题不会作为未经核验的报道标题。

## 供 Rendition 与同步消费的固定契约

| 契约 | 新版本与不变量 |
| --- | --- |
| 生产输入 | SixEditionRequest `schemaVersion: 2`；支持已有输入 Evidence Bundle v1（fixture）/v2（collected），显式六栏证据分配 |
| Report Record | `schemaVersion: 3`、`editorialContract: observer-canonical-v1`；仅选定的已核验 stories、六栏选题关系、分析引用、真实 editionRuns、Gate 账本与许可元数据 |
| Report Version | `schemaVersion: 2`；当前仍是初始 `version: 1`，ID `${businessDate}-v1`、Record ID `${businessDate}-v1-record`；不实现更正或覆盖 |
| 内容绑定 | `reportRecordSha256` 为 UTF-8 `JSON.stringify(ReportRecordSchema.parse(record))` 的 SHA-256；`canonicalMarkdownSha256` 为存储正文原始 UTF-8 字节 SHA-256 |
| 发布与读取 | Record/Version/Markdown 在同一 SQLite INSERT 保存；读取新版本时检查日期/ID/发布时间、两个摘要、Claim→Gate 摘要/结果、标题/栏目/分析引用及 Record→Markdown 精确重投影 |
| 后续呈现 | PDF/邮件 HTML/客户端只消费这一 Report Version 的存储 Markdown；Overview 可取本版本导航子集。不能独立改写数字、来源、标题或事实。内容修改必须重新核验并由未来版本流程生成新刊次版本 |

哈希用于内容关联和损坏检测，不是对来源事实的证明或归档的数字签名。陈述支持依然来自外部 Semantic Assessment；本票仅用标注替身验证流程。自由成稿没有发布入口；即使有人在恢复的归档中改写正文数字并重算正文哈希，新 reader 仍拒绝与 Record 不一致的正文。

`observer-canonical-v1` 的投影和新 Record/Version 字节契约需长期固定；未来编辑规则变化应增加明确的新契约版本与 reader 分支，不能用当前 renderer 静默重生成旧正文。存储格式仍是 SQLite user_version 1，未迁移/重写旧行。ReportRecord v1/v2、ReportVersion v1 继续原样读取，旧 ProduceRequest v1 继续原路径生产；旧版正文不会套用六栏 renderer。原始来源 content 不进入永久归档；来源分发授权撤回后的读取拒绝逻辑保持。

## 独立审查后的有界核验与身份隔离

首轮冻结 `ac55dc418425d02030441156bf9eef9224873f1c` 的完整回归虽绿，独立 Spec 仍发现两个阻断：整期聚合超过单回执 500 Assessments 的合法输入被全部拒绝；局部重复身份使本来正常的核验关系一起失败。该冻结不作为已接受结果。修复仍从原有 produce → readReport seam 进入 Gate，不增加成稿或 Report Record 写入口。

新的 `evaluateBatchedPublication` 是六栏核验的 Coordinator，按固定栏目顺序、保留完整 Story，贪心组成每批最多 500 Claims。每栏最多 50 Stories、每 Story 最多 50 Claims，因此每栏最多 5 批、整期最多 30 批，覆盖 15,000 Claims 的完整合法上限。只有加入下一 Story 将超额时才关批，此时当前批至少 10 Stories；50 Stories 不可能形成第 6 批。所有输入均接受核验后再按每栏约 7 条的软目标选择，不预裁候选，不放宽 Verification v1 的 500 上限。

Report Record v3 新产物使用 Publication Gate `schemaVersion: 2`：顶层 `verification: null`，`batches` 最多 30 个真实 Gate v1 身份/输入摘要/回执/完成时间条目。每批 taskId 为 `verification-${SHA256(JSON.stringify([整期 taskId, 从 0 起批序号]))}`，在旧 200 字符核验身份边界内；每个输入独立哈希，错误或重放回执只能拒绝本批。顶层 inputSha256 是 `{ schemaVersion: 2, taskId, evidenceBundleId, configurationId, batchInputSha256s }` 的规范 JSON 摘要，标识协调计划，不假装为未实际执行过的整期语义回执。空输入的 batches 为空。Record v3 仍可读取原 Gate v1 账本；Record v1/v2 与旧输入沿用原分支，未重写旧 JSON/Markdown。

各批实际送核之前由既有 Gate 重新做模型许可和 TTL 检查。最后一批完成后，所有原可发布/待确认 Claim 再以同一个最终 publication timestamp 检查发布许可与 TTL；之前已核验但到最终时刻过期的材料被隔离，并从正文和归档 Evidence 中移除，真实早期回执仍保留审计。后续批不再发送过期材料。引语原文/译文的来源配额仍由 Observer 在整期范围累计，批次不会重置配额。

结构身份检查先于外部核验投影：同栏或跨栏 Story ID 重复时隔离全部同名故事；同一故事中 Claim ID 重复时隔离所有重名 Claim；单 Claim 重复 Evidence 引用时隔离该 Claim。其他唯一身份仍参与核验和发布；原始整期 Story 集合作为所有批次的身份范围，不能通过分批掩盖跨批冲突。全局 Bundle Evidence 身份、task/config/Edition 关联错误保持原拒绝行为，不能用局部降级掩盖错误。

## 验收映射与未验证

AC-01：足量、稀疏、全空、单栏失败/坏结构、候选拒绝、六栏总览和内容缺口由新增公开测试覆盖。AC-15 本票部分：同版本 Record/Markdown 的标题、数字、来源、状态和内容摘要一致；重复生产不可覆盖，恢复后的正文篡改被拒绝。

PDF、邮件、HTML、Android、真实来源适配、真实六研究进程编排、跨天去重、主题专门规则、调度/恢复与生产准入均未实施。真实模型的中文表达/事实质量、来源授权、目标生产环境、人工阅读和其他 Rendition 一致性未验证。生产模式继续禁用发布并隐藏所有 fixture 版本；任何本地绿灯都不代表正式开闸。

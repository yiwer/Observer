# V1-22：保留期限与权利删除

统一生命周期由 `retention.ts` 管理。服务启动、独立每秒tick及归档/后台任务入口执行维护，不依赖每日调度启用；常规到期工作默认每分钟一次，失败任务持续重试。先持久写入来源阻断与版本删除标记，再清理各存储，失败不解除读取限制。恢复来源配置、重启或重新应用契约均不会解除阻断。

原文和社交样本继续使用各 Source Policy 的有效期；采集库、冻结任务、社交样本及更正候选文本都加入维护。更正候选随其精确来源缓存失效而清空，保留终态去重身份。普通采集及独立 collect CLI每次实际网络请求、重定向和响应完成时检查当前策略。来源撤销的在途结果不能保存或继续分发。Agent原始CLI输出/Prompt原本只在内存与隔离容器中使用；既有空任务目录由执行器清理。本票不遍历或删除任何旧目录。新增 `agent_events`仅记录固定的Provider与路由状态，不含正文/Prompt/凭证，30天删除；报告中的最小执行回执仍作为允许的发布依据保存。

来源策略收紧、移除或本地删除要求触发权利删除。来源与报告依赖从结构化provenance追踪，包含Completion父版本、schema12继承片段及其来源版本；递归处理关联副本。整份受影响报告的Record/Canonical MD替换为明确墓碑，PDF BLOB删除；冻结任务、社交副本、候选文字、关联路由元数据、巡查引用、归档事件和邮件元数据同步清理。正文不可变触发器仅在独立权利删除事务内临时撤下，原定义在提交前恢复。普通编辑没有这个入口。来源删除也覆盖GitHub派生索引和计数副本；不恢复旧安全状态不明的索引链。

墓碑默认仅包含阻断所需的来源/版本定位、时间、原因及最小版本索引。`retainVersionAudit`需要显式选择且当前来源允许记录身份，才能保留发布时间/修订类型；来源内容、URL、引文、原文哈希不进入删除契约。历史/同步显示 `rights-removed` / `rights-tombstone`；latest继续指向真实最新版本，正文、MD/PDF和已签发下载返回410，不回退旧正文。恢复客户端必须消费删除事件清除已缓存副本；已经下载到客户端的文件无法在服务端擦除。

已发邮件及附件不能远程删除。`rights_email_scope`记录已接受/未知/发送中的不可撤回范围，邮件状态接口展示该范围；清理发件/收件地址和Provider元数据，但保留通知ID、交付ID与accepted/delivered/unknown等终态，阻止重启后重发。未发送项置suppressed；发送前继续复用当前权利与签名下载检查。在途SMTP的远端结果可能不可确认，按unknown处理。

GitHub超过90天的观测写入每来源/每天/稳定node ID的最后一次观测；只删除未被发布输入或context/momentum索引依赖的小时run，原始被引用输入保持原字节。每日计数和名称历史单独保存；报道历史与事件去重仍来自原报告，不清空。`retainedDependencyRuns`明确解释保留原因；启用完整momentum链时，其仍需要的小时输入可能全部保留，这不是声称已经压缩这些依赖。排序版本、样本、报道历史、已发表数字及其精确输入不变。

本地管理只打开运行配置明确指定、已存在的管理数据库，不构造Provider、不读取凭证、不采集、不发送SMTP：

```sh
npm run retention -- --config config/runtime.json run
npm run retention -- --config config/runtime.json status
npm run retention -- --config config/runtime.json remove data/operator/rights-request.json
npm run retention -- --config config/runtime.json contract
npm run retention -- --config config/runtime.json apply-contract data/operator/current-suppression.json
```

删除请求为 `{"sourceId":"reviewed-source","reason":"source-request","retainVersionAudit":false}`。这是持久来源撤销；同一来源ID不会因新策略自动解禁。契约schema1包含 `kind: observer-rights-suppression`、sources与versions，可由#24在恢复后、开放任何读取或任务前调用 `applyDeletionContract`，或在运行配置设置 `retention.restoreContractPath`。恢复必须使用备份之外保存的最新契约，先合并阻断再执行清理；不能只从旧备份恢复旧删除表。失败必须保持服务关闭。#24普通备份必须排除 `private_access_meta` 的signing_key及所有环境凭证，恢复时重新签发设备/下载凭证。本票没有实现离机备份、密钥备份或部署。

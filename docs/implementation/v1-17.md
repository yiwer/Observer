# V1-17：私有归档、设备配对与同步

现有发布事务接入 SQLite 持久变更流；生产 Reader 继续拒绝测试报告，全部正文沿用原有来源权限与完整性检查。没有外部调用、Android App、网页管理、通知或部署。PDF 后续已由 [#18](v1-18.md) 接入整刊生成、状态同步及下载；本文件其余验证结果仍描述 #17 当时范围。

## 本地管理

Node 24.18+ 的 24.x。服务仍使用原启动配置和至少32字节随机 `OBSERVER_OWNER_TOKEN`；该秘密只通过环境交给服务和受信 Owner 调用方。设备不需要 Owner Token。下面的数据库路径必须是正在运行的服务实际数据库，使用运行配置时取其中解析后的 `databasePath`。

```sh
npm run devices -- --database data/observer.sqlite pair
npm run devices -- --database data/observer.sqlite devices
npm run devices -- --database data/observer.sqlite revoke <device-id>
```

`pair` 在本地终端仅返回一次 `{schemaVersion:1,pairingId,code,expiresAtUtc,maxAttempts:5}`。将 pairingId 和 code 交给待配对设备，调用 `POST /v1/devices/pair`，JSON 为 `{pairingId,code,deviceName}`。成功为201，返回 `{schemaVersion:1,deviceId,credential,expiresAtUtc}`。请直接安全保存 credential，不记录响应正文。没有远程签发、设备清单或撤销管理接口；文件系统访问权是本地 CLI 的管理权限。CLI 只初始化身份表，不启动采集、Provider 或调度。

配对码采用96位随机值，有效10分钟，最多5次有效结构的尝试，单次成功后原子消费。所有结构有效或无效的 JSON 配对尝试另共用持久全局每分钟30次限制，未知 ID 同样计数；达到限制为429和 `Retry-After: 60`。旧码、失效码、重复消费、错误码统一401 `invalid-pairing`。成功消费与设备插入在 `BEGIN IMMEDIATE` 中一起提交，失败尝试也提交计数。请求体最大4KiB、HTTP请求期限15秒。

设备凭证包含随机 UUID 和256位随机秘密，90天到期；到期重新配对。数据库仅保存配对码/凭证 SHA-256 摘要，不保存可恢复的设备秘密。撤销幂等、持久化，并在每个 Bearer 和签名下载请求中重新检查；没有进程内认证缓存或远程刷新令牌。丢失成功配对响应需重新签发本地配对码。Owner 环境密钥是独立受控引导身份，可通过替换并重启撤销旧 Owner 访问。

## HTTP v1

除配对消费和对象签名下载外，全部路由要求 `Authorization: Bearer <Owner或设备凭证>`；无效凭证401。响应均 `Cache-Control: no-store`，下载另有 `Referrer-Policy: no-referrer`。服务仍只监听127.0.0.1；外部访问需 #23 配置 HTTPS 反向代理，禁止在代理访问日志记录签名下载查询参数或 Authorization/配对响应。

| 路由 | 行为 |
|---|---|
| `GET /v1/archive?limit=50&cursor=…` | 日期倒序的历史，包括仅有调度状态的日期、Missed Brief |
| `GET /v1/archive/YYYY-MM-DD` | 当前完整版本索引、latest、前后版本关系、撤回标记和日期交付状态 |
| `GET /v1/archive/YYYY-MM-DD/latest` | 索引加当前版本完整 `{version,record,canonicalMarkdown}` |
| `GET /v1/archive/YYYY-MM-DD/versions/N` | 索引加精确版本完整报告 |
| 上述 latest / versions/N 加 `?edition=world-affairs` 等 Edition ID | 从该版 Canonical 全文截取完整栏目，带内容来源版本、缺口及当前交付状态 |
| `GET /v1/reports/YYYY-MM-DD-vN` | 保留原精确版本 JSON，Report Record 是该次研究底稿 |
| `GET /v1/reports/YYYY-MM-DD-vN/markdown` | 保留原精确版本完整 Markdown |
| `GET /v1/briefs/YYYY-MM-DD` | 保留原当前调度交付状态 |
| `GET /v1/sync?limit=50&cursor=…` | 按 sequence 升序的持久变更页 |
| `POST /v1/reports/YYYY-MM-DD-vN/download-link?format=markdown` | 授权身份申请该对象的5分钟短期下载，可选 Edition |
| `GET /v1/downloads/YYYY-MM-DD-vN/markdown?token=…` | 凭对象签名下载，签名固定版本、格式、Edition、期限和身份 |

Edition ID 沿用六栏契约：`world-affairs`、`ai`、`finance`、`frontier-technology`、`social-discourse`、`github-projects`。未知栏目400；旧版没有对应正文区块时404，不拼造栏目内容。下载签名路径通过响应 `path` 返回，属于敏感短期能力；不含设备原始凭证，不能换版本/格式/Edition。撤销设备后即使签名尚未过期也401，重新启动不会恢复；报告撤回或来源当前权限撤销后也拒绝读正文。Owner签名亦绑定当前Owner密钥，替换后失效。签名密钥持久存在身份库，数据库必须仅向服务与本地管理者开放，不应当作为普通内容备份公开。

`versions[].version` 是不可变生成快照。`status` 是 `current | superseded | withdrawn`，`supersededByVersionIds` 与 `previousVersionId` 给出修订关系；latest 是最高数字版本，撤回后仍保留该身份，不静默回退到旧内容。撤回正文返回410，日期索引仍可查询。版本的 `timing` 保持生成时快照，初版可能永久 pending；`delivery.timing/onTime` 按首次私有读取探针确定，未探针是 pending/null。`content`、`timing`、`missedAtUtc`、`recovery` 分开，未知旧版状态保留null。

Completion 的 `record.stories` 仅包含本次新研究，不能据此重建完整日报。客户端应使用保存的 `canonicalMarkdown`，栏目 API 同样从完整 Canonical 截取，`contentSourceVersionId` 指向实际提供该栏目文字的版本。`availableEditions` 包括继承的有效研究，`completedEditions` 标明本次补齐；缺口原样保留，链接降级不是研究完成。PDF 的 `available:false,reason:not-generated` 是格式缺失，不是报告内容缺失。

## 分页与同步语义

所有列表包装 `schemaVersion:1`，limit为1–100，默认50。cursor是服务签名的版本化不透明值，绑定归档实例和用途，客户端不要解析或修改。恢复旧数据库导致游标超过现有高水位时409 `cursor-reset-required`，重新完整同步；错误签名/用途400。凭证撤销401，重新配对前停止同步。

历史列表第一页捕获固定 `snapshotSequence`，以后各页均按该高水位重建日期状态，日期倒序、日期唯一；翻页期间新增版本不会改变旧页内容，也不会挤掉尚未读取日期。`nextCursor` 直到最后为null。将同页 `syncCursor` 保存为完成整个历史快照后的增量起点，不能先保存再遗漏历史后续页。

同步第一次不带cursor从0读取，捕获高水位，返回 `{events,hasMore,nextCursor,snapshotSequence}`。`events` 为 `{sequence,eventId,kind,businessDate,versionId,occurredAtUtc,snapshot}`；sequence按升序传为十进制字符串，唯一事件ID用于本地幂等。分页固定 until，高水位之后的变化在本轮完成后的下一次主动同步返回。最后一页的nextCursor仍有值，是下一轮起点；不要用报告日期或发布时间代替。固定分页cursor重复获取得到相同事件；已追平的尾部cursor再次获取允许包含后来新增事件。空页也应提交返回cursor。

`report-published` 携带版本与栏目状态快照，含 Completion 前版本关系；客户端据此更新取代关系。`brief-state` 携带当时公开调度状态，含迟到、缺刊、恢复关闭及首次可读确认。`correction` / `withdrawal` 是 #20 可使用的受控变更事件，含目标、替代版本与原因引用；客户端需保留撤回 tombstone，并在看到撤回时删除/隐藏对应本地缓存正文。变更事件不自动携带全文，刷新受影响日期索引后按需要取准确版本正文。

Report INSERT、调度 INSERT/可见字段 UPDATE、受控修订记录 INSERT 的 SQLite trigger 与源变更在同事务写入 `archive_events`。重启不漏变化，不依赖 outbox 消费。首次升级在同一事务回填现有报告与当前调度快照；无法恢复升级前逐次状态变化，这些初始项只是基线，不捏造历史事件时间。事件 `occurredAtUtc` 是数据库记录时间，报告真实发表与可读时刻在 snapshot。当前不裁剪变更流；大型归档优化后置。

受信本地 `observer.recordArchiveChange({eventId,kind,versionId,replacementVersionId,reasonReference})` 留给 #20。相同eventId/内容幂等，不同内容409；Correction要求已存在且声明正确前版本/原因的替代报告。未来正式发布者应在同一发布事务内调用底层 `privateArchive.recordRevisionChange`。该入口不校验纠错证据，不能代替 #20 的正式流程；本票没有执行真实更正或撤回，没有远程编辑入口。

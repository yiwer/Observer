# V1-15：持久日调度与私有原子发布

已接通 `main.ts → production-runtime.ts → Observer → Provider routing / Publication Gate / Final Editor → SQLite Report + delivery_outbox → 私有 HTTP GET`。默认不开启，没有执行真实来源、Provider、SMTP 或部署。既有替身归档仍不向生产 Reader 开放。

## 运行

Node 24.18+ 的 24.x；首次安装锁文件依赖后 `npm run build`。从 [runtime.example.v1.json](../../config/runtime.example.v1.json) 建立自己的运行配置，设置 `OBSERVER_RUNTIME_CONFIG` 为该文件路径，以及至少 32 字节的 `OBSERVER_OWNER_TOKEN`，再 `npm start`。配置中所有文件路径相对于配置文件；设置运行配置时数据库路径由该文件决定。Owner Token 不放进配置文件或 URL。

配置 `schedule.enabled: true`、`startBusinessDate` 后才会创建日任务。日期以 Asia/Shanghai 计算，UTC 持久化；每期窗口为 `(前一天07:30, 当天07:30]`，私有可读期限为当天08:30。时钟每秒检查；实际冻结时间如实保存，不将启动较晚的冻结伪装成准点。

`collect: false` 消费 `collectionDatabasePath` 的已有缓存，适合与既有 `npm run collect` 进程共用；两个进程必须使用同一份来源配置及缓存路径。`collect: true` 在同一运行入口驱动经政策授权的采集；长采集不阻塞每日冻结。Source Policy 的内容和版本在启动时确定，变更文件后应重启；运行中模型/发布/读取仍检查当前权限，撤权不能被冻结配置恢复。

无已批准来源、没有 Provider 配置，也能发布明确六栏缺口的开发演示。它不意味着完整日报或真实研究已上线。

### Provider 配置

`providers` 可分别配置 `codex`、`claude`，形状为：

```json
{
  "enabled": false,
  "image": "operator-prepared-fixed-cli-image",
  "eligibility": {
    "version": 1,
    "provider": "codex",
    "enabled": false,
    "accountEligible": false,
    "regionEligible": false,
    "scope": "live",
    "checkedAtUtc": "2026-09-08T00:00:00.000Z",
    "validUntilUtc": "2026-09-09T00:00:00.000Z",
    "evidenceReference": "operator-reviewed-qualification"
  }
}
```

该示例没有授予账户/地域资格。实际启用须填写真实受信资格及固定 Linux/amd64 镜像。Codex 使用现有固定 CLI 0.153.4、`gpt-5.6-sol` 和 `OBSERVER_OPENAI_API_KEY`；Claude 使用固定 CLI 2.1.252、`claude-sonnet-4-6` 和 `OBSERVER_ANTHROPIC_API_KEY`。密钥只在显式启用且资格有效的 Provider 装配时读取，交给现有固定 API broker，绝不存入冻结配置或日志。缺密钥时 Runner 不可用并走既有有界降级。此装配不读取或复用宿主 HOME 的 ChatGPT/Claude 登录文件。

生产路由只接纳 `live` 资格；语义核验必须来自现有真实受控 Verifier，研究结果必须来自匹配 CLI 和 API transport。原进程隔离、清理、最大并发、请求数、轮数、总时长和用量保护保持不变。`routing.limits` 延用 #14，未设置时使用既有默认上限。

### GitHub 与社会 Edition

可选 `github` 配置为 `{ databasePath, configuration, developmentConfiguration?, credentialExpiresAtUtc? }`。两个 configuration 使用既有 `GitHubConfigurationSchema` / `DevelopmentConfigurationSchema`；采集凭据来自 `OBSERVER_GITHUB_TOKEN`，按既有契约仅 fine-grained PAT / public-only / metadata-read-only。未配置有效到期时间或令牌时形成明确缺口。`collect: false` 不读取令牌，只对已有观察生成冻结快照。小时 xx:25 相位沿用现有观察器，只有 `availableAtUtc <= cutoffUtc` 的实际快照入期；截稿后的观察不会替换已保存快照。

Release/GHSA 的可选 development 配置已传入实际观察器；本装配尚未提供 development semantic verifier，因此不能声称这些需要语义判断的重新推广已经可用。已有元数据、排名及缺口仍由真实模块处理。

可选 `discourse` 使用既有 `DiscourseConfigurationSchema`，并接入真实 Mastodon adapter。`collect: true` 时每天07:20–07:30每分钟至多尝试一次样本捕获，按现有分页/响应/政策上限运行；保存 SQLite 中已完成且不晚于07:30的样本，冻结后不再覆盖。发布时只重新核验已有样本的存续与权限，不追加普通新帖子。采样范围和实际捕获时间保持可见；未配置、迟到、缺样或重检失败明确显示 Gap。`collect: false` 可以消费此前保存在同一报告库的样本。

## 持久化与幂等

`scheduled_tasks.business_date` 是唯一日刊键，Report 使用现有 `YYYY-MM-DD-v1`。冻结保存原始请求、来源政策、兴趣快照、discourse 配置与样本、GitHub 完整快照、路由配置、运行配置及运行版本。重试使用已保存输入，不重新选取新证据。Provider 镜像/资格装配或运行版本改变时，旧任务报告 `frozen-runtime-version-unavailable`，避免拿新运行环境冒充原版。

任务状态为 `queued → running → published → readable`，失败按配置延后重试，到最大尝试数为 `failed`。进程启动时会继续已有任务；本机 PID 已退出的 running 任务可重新 claim，活着的进程不会被抢占。崩溃重新 claim 也计入最大尝试数。正常关闭先中止并等待在途工作，再释放本实例持有的任务。没有改写 #14 旧 routing run 的最后观察状态，也没有引入分布式 lease 或自动接管。

Report INSERT、routing published、task completed 和唯一 `delivery_outbox` 事件在同一个 `BEGIN IMMEDIATE` 中提交。失败回滚时 Owner 看不到半成品；发布后重启只做可读探针，不重新生成版本或事件。Outbox 当前只保存 `pending`，没有邮件发送、消费或 exactly-once 声明。

主进程用相同 Owner Bearer Token 请求已启动的 `/v1/reports/YYYY-MM-DD-v1`，收到200并确认版本身份后才记录 `readableAtUtc`。日任务另存实际 `frozenAtUtc`、`completedAtUtc`、08:30期限与 `onTime`。邮件受理不参与准时指标。探针失败保持 published，可在后续 tick 再探测，不重复发布。

可从受信本地 API 读取 `observer.scheduledStatus(date)`；`observer.pendingDeliveries(ownerToken)` 返回待交付事件。没有新增远程管理或发布路由。

冻结中的临时原文与社会样本按原到期时间/当前撤权清理；已失效未完成任务明确失败，不能使用已清理输入重跑。永久 Report 仍只留既有政策允许的归档投影。SQLite 文件删除不构成磁盘取证级擦除。

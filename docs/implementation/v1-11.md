# V1-11 GitHub 候选与快照观察

固定基线 `0cc3ae6c7137f63283b03dd538b177cd440f5915`，对应 [GitHub #11](https://github.com/yiwer/Observer/issues/11)。本票提供可装配的官方协议 Adapter 与持久观察闭环；没有启用真实来源、PAT、模型或生产发布。票末全量结果、冻结 SHA 和独立验收另行绑定，不以设计说明替代 PASS。

## Interface 与装配

[github-observations.ts](../../src/github-observations.ts) 的 `createGitHubObserver` 接受独立 `databasePath`、Owner `configuration` / `policies` / `credential` 读取器、可控 UTC `clock` 和可选外部 I/O Adapter。省略 Adapter 使用官方 HTTPS GET，不是每日手工导入数字的接口。

- `observeDue({ signal? })` 完成一个到期小时观察，返回持久 `GitHubRun`。同实例同时调用合并；已完成 slot 重启后返回原结果。跨进程唯一 slot 保留先提交结果，但没有分布式任务租约，装配应只指定一个采集进程。
- `snapshot(cutoffUtc)` 返回截止前可用、当前有权发布的投影；`authorize(snapshot)` 检查当前配置和来源权利；`close()` 关闭观察库。
- `createObserver({ ..., github: observations })` 的受信装配引用提供数字材料。`produce` Request 7 不接受模型/候选自报快照 ID 或计数；鉴权 `readReport` 返回同一不可变 Report Record / Canonical Markdown。

Owner 配置是 `{ schemaVersion: 1, version, sourceId, queries }`，查询唯一、1–3 个、每个最多 200 字符。配置/来源递增版本及摘要拒绝回滚或同版本编辑。Interest Profile 与配置在异步前固定；来源权限在请求、重定向及 DNS 后发送前、观察提交、出版、读取时重查。直接调用无效配置的观察器可能抛出配置错误；Request 7 会把观察读取失败隔离为本栏 Gap，不以普通模型材料补数字。

调度装配定期调用 `observeDue()` 即可；本票不增加生产进程全局调度器或环境开关，长期调度由后续票负责。

## 来源、秘密与保留授权

来源必须是 Owner 审阅的 `github-projects`，`feedUrl` 精确为 `https://api.github.com`。可选 Source Policy `github` 明确批准 `allowedQueries`、`allowApiResponseProcessing`、`allowRepositorySnapshots`、`allowIdentityHistory`、`allowDerivedPublication`、`irrevocableExportAllowed` 和 `deletionScope`；缺失不是许可，旧策略缺少该字段时原摘要不变。

通用 collection/storage 仍须允许 URL、标题、内容/摘要投影和记录键；出版仍须 distribution 的 URL/标题、派生文本、永久归档及 citation 许可。实际来源署名与有效资源上限进入收据及 MD。数字不发给模型，不要求未使用的 model 权限，也不声称 LLM 核验了计数。未知资格不是恶意检测结论。

`credential()` 的秘密声明是 `{ kind: "fine-grained-pat", token, expiresAtUtc, repositoryAccess: "public-only", permissions: "metadata-read-only" }`，由 Owner 秘密配置供应；令牌不进入 URL、请求正文、配置摘要、SQLite 或报告。到期停止使用。本地权限/到期声明是供应配置证据，GET 成功或可选响应头的缺失不能证明 PAT 最小权限或有效期限。

保留权限分三层，不能混用：

1. `storage.retentionHours` 仍约束原始材料/缓存正文。这里不持久化原始响应或条件响应缓存，不把 raw TTL 延成原文永久许可，也不使合法 24 小时历史数字自动过期。
2. `allowRepositorySnapshots` / `allowIdentityHistory` 明确授权持久结构化累计数、节点/名称、实际时间、语言、创建时间、topics、响应摘要及来源/配置收据。Owner 审阅须包含 D8 小时 90 天后保留每日观察及计算所需输入的语义。当前保留详细观察历史；[#22](../planning/v1/tickets/22-retention-and-rights-removal.md) 明确负责压缩、物理权利删除及已发表输入保留，本票**没有实现自动压缩或物理删除**，不可声称完整保留生命周期验收。
3. 永久 Report 只保存固定投影及实际计算依据，必须允许永久派生和不可撤回导出，并为 `deletionScope: "raw-only"`。未知或要求删除派生导出的来源不能发布。许可收紧阻断继续发布/读取；物理关联清理由 #22 完成。

## 官方协议与有限覆盖

采用完整审阅的 [官方 API 研究](../research/github-api-contract-2026-09-06.md) 和 [元数据字段补充](../research/github-ranking-metadata-addendum-2026-09-06.md)，固定 `X-GitHub-Api-Version: 2026-03-10`、`Accept: application/vnd.github+json`。历史 Trending 研究不是今日协议常量依据。

只 GET `/search/repositories` 和 `/repos/{owner}/{repo}`。搜索在 Owner 查询后加 `is:public fork:false`，`sort=updated&order=desc`；每查询至多 3 页，每页 `min(30, source.limits.maxItems)`，本轮候选至多 `min(50, source.limits.maxItems)`。披露实际有效值、API 总数、收到数量、页数。incomplete 标志、缺少/非法 next Link、页数/候选上限产生 Coverage Gap；分页不是交易一致快照，不保证发现全 GitHub 或所有改名。

仓库重定向至多 `min(2, source.limits.maxRedirects)`，只允许同一官方 origin 的仓库路由，每跳发送秘密前重新检查。搜索不重定向；不跟随 /user、任意同源 URL、README、镜像 URL，不克隆、执行代码或下载二进制。node ID 保持 opaque 原字节，仅长度/控制字符资源约束，不猜编码。

有限 Search 重新发现同 node 新名，或受守卫的仓库重定向确认同 node，形成改名/转移历史。Search 没出现时使用同来源最近验证的已知地址；旧名被另一 node 占用不能串接身份。不同 source 不继承旧源候选。不能确认身份或重新发现时明确隔离/缺样；不采用未文档化数字 ID REST 路由或新增 GraphQL。

必填字段为 node/名称、私有/存档/禁用/fork、nullable mirror、累计数、nullable language 和非 null created_at。visibility / is_template 合法省略不是整批协议错误，但资格未知须隔离，不默认 public/false。数值须为安全非负整数。topics 省略为 null，[] 为明确空；创建时间正规化 UTC。元数据只来自同一次详情响应，不以后查事实填补历史未知，供 #12 复用，不做 cohort/评分或安全保证。

不发送条件请求，不实现 304 复用；意外 304 明确失败。429/限流 403 遵守 Retry-After/reset，至少退避 60 秒，合法最早恢复 UTC 写入 `resumeAtUtc`，重启不提前请求；非法/溢出头不形成无效 ISO 或秘密错误文本。每请求遵守来源 timeout/maxResponseBytes，一轮总时限 120 秒，无即时重试循环。取消、网络、过期凭证、访问拒绝均有脱敏 Gap。

## 时间与不可变数字

每小时 Asia/Shanghai **xx:25** 到期，UTC 持久化；该时区整小时偏移使 UTC 分钟也为 25。错过按实际时刻采集，不把 scheduled 时间回填成观察时间。仍遵守来源实际 `pollIntervalSeconds`：迟到 xx:24 的采集不会在一分钟后的 xx:25 再取一次。

当前选截止前 15 分钟内最近完整观察；历史选 cutoff−24h 前后 60 分钟内最近观察。同距选较早时间，同刻以稳定 ID 打破冲突。完整响应接收、校验完成和材料可用均不得晚于截稿；等于合法，未来不满足“±”容忍。MD 显示两个实际时刻及实际间隔，不把窗口说成恰好 24 小时。

净变化严格由所选两个累计数相减，保留正/零/负。真正 first-seen 晚于历史目标才是 Cold-start Heat；已知项目缺样不冒充冷启动或零。截止前新失败/不合格/未知阻止旧好样本复活；截止后失败不抹去过去有效材料。

独立观察 SQLite application ID `1329746759` / version 1，拒绝错库或未知较新版本；报告 SQLite 不迁移，仍 version 1。完整观察/身份历史留在观察库供 #12/#22 复用；当前公共 snapshot 是出版投影，#12 应在同模块使用完整历史后再做展示选择，不从未来 API 重建历史元数据。

Report 固定所选双快照、最新必要失败/搜索收据和 cutoff 前身份摘要，不重复每一小时历史。名称沿革至多最近 8 次，另存真实 first-seen 和完整截止前名称历史 SHA-256。读取验证固定投影、算术、时间、来源权利，不依赖后来变化的观察库重选；重启保持同一正文。

## 正文版本与普通新闻

新增 Request 7 → Record 8 / ReportVersion 7 / `observer-canonical-v6`。旧 Request 1–6、Record 1–7、Version 1–6 保持原 renderer 路径；新版本通过已有编辑投影继承事件历史、兴趣、领域、社交门。旧版本真实字节兼容由固定报告独立回放验证，不以“可解析”代替字节一致。

Request 7 的 GitHub 是确定性数字编辑模式：普通 GitHub 候选或其他栏中的该源材料局部隔离，留下 `github-ordinary-candidate-unsupported`，禁止正文留存/模型发送；其他五栏继续 Claim/Source 等普通门。六个 Research Agents 的 GitHub prose 不因此成为数值证据，也不为项目任意关联 LLM 链接。

measured/cold-start Watch Item 按 opaque node ID 确定顺序，**资格过滤后**最多 7 个；缺样/隔离另列 Gap，不挤占合格位置，不与普通 GitHub 故事重复占正常目标。本票无正式综合排名、历史衰减、重大进展绕过或安装推荐。MD 含原始项目和 API 链接，明确有限候选不是全 GitHub 或官方 Trending。

## 验证交接

按 Owner 已确认 T1 seam 逐条 RED→GREEN：受控官方形状 HTTP、clock/config/Source、真实 SQLite、produce、鉴权 readReport 和关闭重启。首条 tracer 固定 +5 stars、−2 forks、同 node 改名和两个实际时刻；旧版普通事件历史继续进入连续两天新版本。少量真实 Source Reader / 自有 HTTP 合同测试检查每跳 token 权限及路由。没有真实候选请求或秘密。

局部原始终端位于作者忽略目录 `data/v1-11-slices/`；首个缺模块 RED 只有原 tool 输出，没有补造历史日志。15 号历史 fixture 日期错误不算产品 RED，16 才是有效业务 RED；官方必填 metadata 的 fixture 修正也不算缺陷。已实现失败矩阵的初次 PASS 只称覆盖，不虚称 RED。

复跑时把 TEMP/TMP 指向本工作树独立 `data/author-tmp`，执行 `npm run typecheck`；局部使用 `node --test tests/github-observations.test.ts tests/github-protocol.test.ts tests/github-history.test.ts tests/github-authority.test.ts`；票末 `npm run check` / `npm run smoke`。

check 含固定已有 Docker CLI 镜像的无凭证模型协议替身；smoke 是其中 3 项子集，不另计覆盖。票末证据绑定 clean SHA、命令、UTC、退出码、计数和原始日志 SHA-256。Root 的 fresh Standards/Spec review、旧正文回放及独立业务探针另记，作者不自授验收。真实来源接入、PAT 最小权限、账户/地域资格、生产运行和人工质量仍未验证。

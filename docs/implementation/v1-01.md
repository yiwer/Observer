# V1-01 实现与验证

范围依据：[GitHub #1](https://github.com/yiwer/Observer/issues/1)、[本地 ticket](../planning/v1/tickets/01-private-brief-spine.md)、PRD D1/D2/D3/D9/T1 和 ADR-0001。基线为 `99d7fb5fd3873786d2510fc6ccbf230997a07374`；实现提交由本文件的 Git 历史识别，不以文档内自引用 SHA 代替代码版本。

## 公共接口和最小契约

`createObserver({ databasePath, ownerToken, mode, clock?, runner? })` 返回 `produce(input)`、`readReport(versionId, credential)` 和 `close()`。`produce` 是 PRD T1 已确认的整期 seam：输入业务日期、配置标识、任务标识和固定来源材料，由可控时钟与 AgentRunner 返回可观察的 Report Version；测试通过 `readReport` 或 HTTP 获取发布结果，不读取数据库表来断言业务结果。

`src/contracts.ts` 是 schema version **1** 的运行时定义及 TypeScript 类型来源，使用严格对象拒绝未知字段/版本。兼容扩展需要显式演进 schema 并由 orchestrator 协调，不能静默赋予旧 fixture 生产资格。

| 对象 | v1 最小语义 |
|---|---|
| Evidence Bundle | 业务日期、配置、窗口和截止 UTC；来源稳定 ID、直达 HTTP(S) URL、来源类型、可未知事件/发布时间、发现/获取 UTC、允许的测试内容及 SHA-256 |
| Candidate Story | 故事和事件 ID、主 Edition、标题、逐陈述 `evidenceIds`；引用必须在本 Bundle 中 |
| AgentRunner | `run(ProduceRequest): Promise<unknown>`，输入/结果带 schema version、任务/配置/Bundle ID；结果始终经过结构和关联校验 |
| Agent result | `succeeded` 有故事；`failed`/`cancelled` 有 failure category/retryable；模型、runner version、开始/结束 UTC、可选 input/output tokens 和 USD 用量 |
| Report Record | 业务时区 `Asia/Shanghai`、业务日期、完整 Evidence Bundle、配置和应用版本、任务与 Agent 终态、一个故事、五个缺口、显式 `test-fixture-only` 来源决定 |
| Report Version | 稳定刊次/版本 ID、初版序号 1、实际发布 UTC、初版原因、前版空值、Record ID、Canonical Markdown 哈希及 `test-fixture` provenance |

持久化时间要求 `YYYY-MM-DDTHH:mm:ss.sssZ`，日历日期必须真实有效。未知事件/发布时间保持 `null`。测试出版限定一条故事；这不是已实现六栏选题规则。Markdown 保存后直接返回，后续派生内容必须使用保存的正文，不能重新调用 Agent 生成同一版本。

`produce` 拒绝坏请求、Bundle 身份/哈希/截止窗口不一致、未关联的 Agent 结果、未完成/坏结构/失败结果和未知证据引用。典型稳定错误码为 `invalid-request`、`invalid-bundle-identity`、`evidence-integrity-failed`、`invalid-evidence-window`、`uncorrelated-agent-result`、`agent-invalid-output`、`agent-timeout`、`agent-cancelled`、`unknown-evidence-reference`；Runner 抛出的任意异常统一为 `agent-unknown`，不传播外部异常文本。失败不生成可读取版本。最小流程不持久化失败任务历史，也不重试。

生产模式调用 `produce` 返回 `publication-disabled`；读取先鉴权再查归档，缺失/错误凭证为 `unauthorized`。同一期不可覆盖，即使完全相同输入再次生产也返回 `version-already-exists`；调度幂等、Correction 和新版本关系由后续票完善。

## 红绿证据

以下每条先观察到失败，再加入对应最小实现；每轮运行目标测试文件，若干轮独立运行 typecheck。第一次 SQLite 测试的清理曾因 Windows 文件仍打开出现 `EBUSY`，修正为先关闭连接再删除临时目录后通过。

| 切片 | 红灯观察 | 绿灯结果 |
|---|---|---|
| 一个故事、五栏缺口、Owner 读取 | `src/observer.ts` 不存在 | 已鉴权内容/版本及拒绝读取通过 |
| Agent 任务关联 | 错任务结果被发布，缺少预期拒绝 | 跨任务/Bundle/config 结果拒绝 |
| 证据关联 | 未知证据引发未分类 TypeError | `unknown-evidence-reference`，归档无版本 |
| 内容哈希 | 修改内容仍发布 | `evidence-integrity-failed` |
| 截稿快照 | 截稿后获取仍发布 | `invalid-evidence-window` |
| 版本、日期、UTC 结构 | Zod 异常未转成业务错误 | `invalid-request` |
| Bundle 身份 | 日期/配置不符或证据 ID 重复仍发布 | `invalid-bundle-identity` |
| Agent 失败/部分输出 | 非终态坏结构未分类 | 结构拒绝，timeout/cancelled 不发布 |
| Fixture provenance、运行时间 | 伪装 codex 或矛盾时间仍发布 | `invalid-fixture-run` |
| 确定性及不可覆盖 | 重复出版抛原生 SQLite 错误 | 两个新归档内容完全相同；重复出版给稳定错误且旧版不变 |
| 真进程重启 HTTP | HTTP 入口文件不存在 | 写入进程正常退出，新进程读取相同 JSON/正文；401 无内容 |
| 生产入口隔离 | 初建生产入口后 fixture 读取为 200（应为 404） | fixture JSON/Markdown 均 404；POST 405，测试环境标志无效 |
| Runner 异常 | 外部异常正文直接传播 | `agent-unknown`，无版本 |

验证环境：Windows、Node **v24.18.0**、npm **11.16.0**、SQLite **3.53.1**、TypeScript **5.9.3**、Zod **4.1.12**。实现完成后运行 `npm ci --ignore-scripts --no-audit --no-fund` 成功重新安装锁定的 4 个包；`npm run check` 的 typecheck、构建及 **13/13** 测试通过；`npm run smoke` 构建及 **2/2** 进程测试通过。该结果属于此文件所在的实现提交；审查若引起代码修改，须在新的冻结提交重新验证。

本票证明的是固定材料/替身的本地能力及真实进程持久化；真实采集、模型事实质量、六栏选题、调度、PDF、邮件、设备认证、Linux 部署和生产准入均未验证。结构和引用存在性检查不证明陈述被来源事实支持；来源许可、事实质量与生产装配必须由后续票实现并单独验收。

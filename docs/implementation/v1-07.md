# V1-07 — Event Cluster、跨栏去重与跨日报更新

范围：[GitHub #7](https://github.com/yiwer/Observer/issues/7)，固定起点 `5da81976dd2ba166066977c038e6f46451890283`。实现和测试采用已确认的 PRD T1：`createObserver.produce → readReport`，真实 SQLite、可控外部 Research Runner / SemanticVerifier / 来源策略 / 时钟。测试不调用内部事件函数、不通过 SQL 观察历史；重启后的后续生产和旧版本读取验证持久化。

## 身份与证据判定

Research Agent 提供候选及 Claim；独立的外部 SemanticVerifier 评估事实支持，并可对身份锚 Claim 提供 `event`：subject/action/object/discriminator 四个身份成分、规范化的独立事实 `fact`、主 Edition 建议、重大性及其 analysis Claim 引用，以及发生/首次披露/进展的 Evidence 引用。`disclosureEvidenceId` 的语义是“此证据首次公开披露这一个事实”，不是所有来源的 publishedAt 自动成为首次披露。

普通事件优先以已通过 Gate 的 `fact` 为身份锚。同一候选所有事实锚必须有有效且一致的事件注解；缺失、错误引用或不一致会留下明确缺口。辅助 publisher statement 和 analysis 保持各自类型，不自动成为另一事件，也不要求为了保留合法辅助声明而虚构事实。没有 fact 的候选可使用正确归因的 statement 作为“发布声明”事件：显式 `eventKind: publisher-statement`、subject 等于该 Claim 的实际 publisherSourceId，action 必须为 `published-statement`，发生和进展引用必须为 null。声明内容依然是声明，不能升级为发生事实。事实事件与声明事件的身份空间分开。

Observer 在最终 Gate 之后生成 `observer-final-event-projection-v1`。原 `event` 归一化自由文本从所有请求版本的永久回执中移除；仅最终通过 Gate 的事实/合格声明留下 schema-validated 注解摘要、身份摘要、事实摘要、固定枚举和合格引用。身份字符串只做 NFKC、空白折叠和大小写规范化，再连同 eventKind 摘要化。Cluster ID 和 Development ID 由这些摘要派生，既不使用候选 ID 作为权威，也不以字符串相似度或 materiality 布尔值直接授权。

投影明确属于 Observer，保留原 Verifier 身份和原核验 inputSha256；不声称是未修改的外部回执。外部自行提交 eventProjection 会使该回执无效。原文、标题归一化文本、注解自由文本均不因这个步骤进入永久档。未知/错误引用不被原样当作元数据文本留下；重大性引用只保留最终已核验 analysis。

语义等价性和 materiality 仍是外部评估，不是哈希或 schema 的事实证明。固定标注替身证明的是约束、关联与重放行为；真实模型的语义归一化稳定性和错误率未资格验证。原有事实证据 Gate（适当一手/独立来源、归因、冲突、引语与 TTL）先于事件选择；事件规则不能补足未通过 Gate 的事实。

## 可执行选题与冲突表

表中“本期”是 `(windowStartUtc, cutoffUtc]`；窗口左端不再次当作今日首次披露。所有时间 UTC，业务日期仍显式 Asia/Shanghai。

| 条件，按先后处理 | 结果 |
| --- | --- |
| 当前来源权限、TTL、语义或结构 Gate 未通过 | 不进入事件身份；保留既有 Gate 缺口/隔离账本 |
| 有此前已发布的 Record1/2/3 新闻，但没有已核验事件身份 | `legacy-history-unclassified`，本期新闻候选不宣称“从未报道”；GitHub 专门规则不受此新闻迁移缺口冒充实现。旧刊仍可读且不改写 |
| 身份锚缺注解、注解不可用、主语/事件种类不匹配 | `event-assessment-unavailable` |
| 时间证据不是本 Claim 的受支持可靠 Evidence，或一候选事实锚属于不同身份 | `event-assessment-invalid` |
| 声称发生/进展时间晚于披露或 cutoff，或披露晚于取得材料 | `event-time-conflict`；不把未来计划写成已发生 |
| 同一身份的已知发生时间互相矛盾（含历史） | 整个当前冲突组 `identity-conflict`，不任选一个事实时间 |
| 相似关键词/同一个候选建议 ID，但已核验身份不同 | 分开 Event Cluster，各自选题；不强并 |
| 该 Cluster 的全部 Development Identity 都已刊登 | `no-new-development`；新标题、新候选 ID、新来源和发现时间不产生新事实 |
| 有未刊登事实，但首次披露未知 | `unknown-disclosure`，不会借发现时间填补 |
| 首次报道，未刊登事实在本期首次披露 | `new-disclosure`；事件发生很早仍可入选 |
| 已报道事件有本期首次披露的新事实，重大性且 analysis 引用都有效 | `material-update`，关联前次版本与故事 |
| 未刊登事实的披露早于/等于窗口左端，仍有有效重大性分析 | `late-discovered`，明确补报；既适用于新 Cluster，也适用于已报道事件的漏采重大进展 |
| 旧披露/再报道缺重大性、重大性只是 routine 或没有合格 analysis | `not-material` |
| 合并后的主故事超过正常栏目软目标 | 正常选题容量限制；对应选择账本标为 withheld，不把未刊登的 Cluster 当历史已报道 |
| 后续事实支持将旧误关联分开 | 要求显式 distinct-event 评估、实际旧版本/Cluster 存在、当前身份不同、建议对应旧 Cluster、basis 是当前事实锚；只记录 `separatedFrom` 后续拆分关系 |

每个事实分别有 Development Identity 与披露时间。组内早披露的旧事实不会遮蔽另一条今日首次披露的新事实；多个符合条件的独立进展放在同一主故事内，来源关联保持原 storyId/claimId。只有实际主故事或其附加事实显示的 Development Identity 才计入已报道历史；仅存在于未选候选中的事实不会被误当作已经刊登。

拆分不修改旧 Record、旧正文、旧哈希或旧关联，不设置正式 Correction/撤回状态，不发纠错通知；这些仍属于后续更正流程。无法证明拆分关系的建议留下缺口，不能根据一个旧 ID 自动修改历史。

## 主栏、Impact Note 与容量

先基于合格新事实选择该组可作为主故事的候选，再优先使用有证据注解支持、且确有合格候选的主 Edition 建议；无可用建议时按固定六栏顺序和原候选顺序选择。决定、成员、证据和实际版本/故事均持久化。去重发生在每栏约 7 条/约 3 重点选择之前，剩余合格候选可补到正常配额，Impact Note 永远不进入普通 storyIds 或 priorityStoryIds。

一个 Cluster 在本期只有一个主故事。其他栏使用同版本主故事锚点和明确 versionId；优先保留现有有效 editorial Impact Note，自动成员注记使用该成员已核验的重大性/影响分析，最多一条分析作简短解释。缺分析显示影响说明缺口，不能编造影响路径。不会同时重复生成已有相同目标栏的有效注记。

单候选 50 Claims、单栏 50 Stories、核验每批 500 Assessments、整期最多 30 批的既有输入上限不变。多候选合并不会把它们强塞进旧 Candidate 的 50 Claims 结构：附加事实保留原身份并在主故事内呈现，因此 98 条独立事实仍能归为一个主故事。GitHub 候选保留既有六栏成稿能力，本票 eventSelections 标明 `github-rules-deferred`；仓库身份、热度、风险和冷却均未在这里实现。

## 时间与历史权限

发生时间、首次公开披露、首次发现、实质进展时间分别保留，未知值为 null。时间只取授权归档元数据中由合格身份锚引用的字段，不让模型输出任意时间。每个非空发生/披露/进展时间带 Evidence ID 和来源 Report Version；发现时间取该事件已有历史与当前证据的最早取得记录。原 eventTime 为空不会由 published/discovered 日期代替。多个事实的披露分别保存；组级实质进展时间是本次材料明确记录的最早进展时间。

历史从同一 SQLite 不可变报告行重建，没有新的测试历史入口，没有内容缓存迁移，也不静默截断历史。只取 businessDate 更早，且 actual publishedAt 和证据 cutoff 均不晚于当前 cutoff 的报告；未来已出版的记录不影响较早日期回放。恢复后先检查历史摘要、Gate/正文投影及事件关系；历史损坏失败关闭，不能当成空历史重新选题。

本地历史去重只比较摘要及版本关系，不向 Research Runner 或 Verifier 重新发送旧来源文字。复制历史时间元数据还要求当前来源允许分发和永久归档，不能因为“不发送模型”就当作有分发权。借入的来源 policy/version/hash 以 historyPolicies 持久化且传递继承；每次读取都复查。先成功刊登再撤销旧来源时，受影响的新旧不可变版本都会拒绝读取，不动态改写正文。

新出刊时遇到旧来源已撤销，仍使用无正文的去重指纹防止旧事实重新刊登；旧来源时间不复制到新 Record，firstDisclosure / firstDiscovery 为 null，并明确 `source-policy-withheld`。当前有效新来源可支持新进展。历史许可缺口与真正时间未知在元数据和正文中可区分。

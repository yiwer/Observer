# V1-03 — 陈述级证据与 Publication Gate

范围为 [GitHub #3](https://github.com/yiwer/Observer/issues/3)、[本地票](../planning/v1/tickets/03-evidence-publication-gate.md)、PRD D5/D6/T1。公开测试 seam 仍为 `createObserver(...).produce(input)` → `readReport(versionId, ownerToken)`；新增外部 `SemanticVerifier` 可替换语义判断。此提交不实现 #4 Runner、#9 高风险规则、调度、真实来源或真实模型调用。

## 版本与兼容

ProduceRequest v1、AgentResult v1 外壳不变；成功结果现在显式接受 Candidate Story v1 或 v2。V2 的每条 Claim 有稳定 ID、`kind`、文字及 Evidence ID 列表。类型为 `fact`、带 `publisherSourceId` 的 `statement`、标注 `explanation/scenario` 的 `analysis`，或带 `originalText/translated/language` 的 `quotation`。一个 Candidate 中可混合这些类型，但不混合 Candidate schema 版本。

V1 只保留在**无 Verifier 的旧 test-fixture 装配**，用于 V1-01/02 的历史回归；一旦注入 Verifier，V1 候选返回 `legacy-candidate-disabled`。旧记录保持 ReportRecord v1，不能被视为已经通过新门。新候选生成 ReportRecord v2，包含独立 `publicationGate`，可为零个可发布故事并展示六栏缺口。新记录使用仅可归档的 ArchivedBundle v3：记录原 Bundle 版本，逐 Evidence 的 `origin` 明确区分 fixture 与 collected；仅 collected 带实际政策版本/指纹，不为 fixture 合成政策身份或 TTL。ProduceRequest 仍只接收采集 Bundle v1/v2，不接受归档 v3 作为研究材料。新旧记录均由现有 SQLite `user_version=1` 的 JSON payload 存储；没有改变表结构或重写旧记录。旧二进制无法理解 v2 payload，读取含 v2 报告的归档须使用此版本或更新版本。本票未发布的 provisional payload 不构成持久化迁移承诺。

所有版本仍是 `test-fixture` provenance；生产装配仍拒绝 `produce`，并拒绝读取 fixture 报告。加入一个 Verifier、改 Provider 名称或设置环境变量都不构成生产准入。

## 语义接口与判定责任

`SemanticVerifier.verify` 接收一次独立副本：task/configuration/Bundle 关联、v2 候选及**仅模型许可视图**的 Evidence，以及完整该输入的 SHA-256。Runner 也只接收副本，不能修改后续核验使用的快照。Runner 返回后、向 Verifier 发送材料之前，重新检查模型许可与 TTL，排除失效 Evidence 及依赖它的陈述；仍有效的陈述可继续核验。Agent 自带标题在此换成中性标签，因为发布标题只从已通过的陈述生成。Verifier 必须返回相同输入摘要、版本/provenance 以及恰好一份对应每个实际送核 Claim 的 Assessment；每个所引 Evidence 必须恰有一份支持关系。重复、缺失、跨 Claim、未知或额外引用、跨输入摘要、坏结构和外部异常都不授权发布。

Assessment 的 `conclusion` 为 supported/insufficient/conflicting/unsafe；`reason` 为固定分类，`wording` 表明可安全展示的原创文字、引语或不安全文字；逐 Evidence 指出 supports/contradicts/irrelevant、direct-observation/publisher-statement/secondary-report、可靠性及 Upstream Origin。这里的 origin 指原始观察/稿件，不是转载网站域名；`null` 表示上游未查明，不计为独立来源。结论与原因必须相容：supported 只接受 supported-by-evidence，insufficient 只接受 insufficient-evidence，conflicting 只接受 source-conflict，unsafe 接受 unsafe-material/irrelevant-evidence。互相矛盾的回执整体隔离，不能择取其中肯定字段授权发布。接口保留 `research-agent` provenance 供后续真实适配器/复核实现；本票所有测试都使用显式 `annotated-fixture`，没有实现或调用真实适配器。

语义实现负责判断**这条具体陈述**是否由材料支持、一手观察是否适合这条事实、来源可靠性和上游沿袭、声明归因、分析是否只是解释/情景、引文是否忠实/上下文是否误导、翻译是否准确、是否夹带指令/抄袭/未经校准的置信度。这些不是词语匹配或类型检查可以证明的。`supported` 不表示概率；契约没有精确 confidence 字段，额外概率字段因严格 schema 被拒绝。正文中的概率性断言仍属于语义核验责任，不能靠百分号过滤器判断。

确定性门验证以下约束：

| 内容 | 发布条件 |
|---|---|
| 普通事实 | 语义支持，且一个被判定适当的 primary/direct-observation，或至少两个可靠、非单方声明的支持项，同时具有不同 Source 与 Upstream Origin |
| 发布者声明 | 支持关系是 publisher-statement，并与候选所归因的 Source 匹配；正文固定显示“发布者声明” |
| 分析 | 有明确语义支持，正文固定显示“分析（解释/情景）”；可以解释一个发布者声明的条件后果，不宣称承诺已实现 |
| 引语 | 单个具体 Evidence；原文确实出现在许可研究内容中；非译文须与原文相同，译文明确标识语言并展示原文；语义支持且 wording=quotation |
| 冲突/不足 | Unconfirmed Item；只有 wording=original 且来源许可通过的安全描述才显示为“待确认说法（非已证事实）”，附近列支持/相反来源、归因与链接，并保留固定中文原因/审计码；不作为已证事实或标题 |
| 无关/恶意/伪引用/未标引文 | 隔离及 Coverage Gap，不把原候选文字归档或显示为事实 |

支持项计数不赋予来源可靠性，也不验证模型判断。正确事实、声明/分析/译文的正常路径与多类失败路径均由固定标注贯穿到真实 SQLite 归档正文。

## 来源许可、归档与复核

结构、来源政策、语义结果分开写入每条 Gate Decision。结构不合格不会伪装成语义反证；政策失败记录为 policy failed/semantic not-evaluated，即使外部回执认为 supported 也不能发布。进入 Runner 之前已失效的政策、坏请求或坏 Agent 外壳沿用 V1 的分类错误，未创建报告；已识别的 v2 候选在门内失败则产生可读取的缺口记录。

核验完成后采样一次完成时间，重新检查来源版本/指纹、类型、模型/分发/永久归档/引用许可、可分发 URL/title 及此时 TTL；该时间同时作为 `publicationGate.checkedAtUtc` 和 ReportVersion.publishedAtUtc，不再取一次较晚时间留下校验空档。到期瞬间不再允许事实发布。旧政策禁止模型时不会先送去模型。引语按 Source 汇总**原文加译文** Unicode codepoint 用量；同源多个 Evidence 共享限额。许可字段独立投影：Verifier 可见 content 并不使 content 可归档，原文引用只使用单独许可的短引语。新归档从不包含 raw source content，即使 Bundle 是旧 fixture v1。

V2 归档保留通过的陈述、语义判定为安全且许可通过的待确认描述、许可引用元数据、送核输入整体摘要、逐 Claim 摘要、所有初始 Evidence 的观察身份/来源/取得时间及有时存在的政策指纹、结构/政策/语义分类与完整有效回执。`verificationEvidenceIds` 区分实际送核材料与发前失效的材料。无效回执和异常文本不会归档；原始被隔离候选、模型可见原文、源 contentSha256（若未获分发许可）不进入报告。输入整体摘要是本次处理的关联收据，不是单源正文的独立哈希字段。不能仅靠摘要重建原文；原始缓存仍只保留最新修订，过期清理照常生效，持久冻结/replay 由 #15 后续处理。

正文仅使用通过的 Claim 生成标题，忽略 Agent 的独立标题；引用标签不复述来源标题。正文、归因和标识符做 Markdown/HTML 文本转义，链接使用许可的 HTTP(S) 目标并防止 Markdown 目标分隔符注入。JSON 记录中的许可来源元数据仍是**不可信数据**，未来客户端必须按普通文本呈现。对于待确认/隔离项，中文原因与固定分类码保留在正文；实际来源、Evidence 和上游关系在结构化核验记录中追查。

## 红绿记录与验证边界

每个用例先观察失败再补最小实现。首个依赖缺失不算业务红灯：先 `npm ci --ignore-scripts --no-audit --no-fund` 安装锁定的 7 个包，然后观察到 `agent-invalid-output`，才实现 v2 正常路径。

| 切片 | 观察到的红灯 |
|---|---|
| 一手事实归档 | 新候选被旧 schema 拒绝 |
| 独立来源/转载 | 两个独立来源仍 unconfirmed |
| 伪造引用 | 抛错而未生成结构化 Gap |
| 回执绑定 | 重复回执仍 published |
| 声明/分析 | 新类型被旧 schema 拒绝 |
| 翻译引语 | 新类型被 schema 拒绝 |
| 无关/冲突/恶意/隐含引用 | 无关材料仅 unconfirmed，缺少正确隔离分类 |
| 末端政策/TTL及独立投影 | 归档正文缺归因；追加核验失败发现空决策列表仍被旧 min(1) 约束 |
| 同源引语总限额 | 两份引语 policy 都错误显示 passed |
| 正文转义/中文解释 | 原始 script/未核验标题可出现在正文 |
| 声明基础的条件分析 | 合格情景仍被当作单方事实不足 |
| 旧候选隔离 | 启用 Verifier 后 v1 仍能发布 |
| Runner 输入副本 | Runner 替换了后续 Verifier 看到的原文 |
| 失败证据可追溯 | 缺少输入 Evidence 身份与取得时间 |

周期执行 `npm run typecheck`、`node --test tests/publication-gate.test.ts` 及相关旧单文件；完整命令为 `npm run check` 和 `npm run smoke`。精确终态计数和提交 SHA 在 ticket 交接中给出。静态/本地自动化与标注替身只验证判定流程、策略和归档，不证明真实事实质量、真实外部来源/模型、人工权利评审、高风险专用规则、生产发布或部署。真实质量仍须 PRD T3 影子评测和后续准入。

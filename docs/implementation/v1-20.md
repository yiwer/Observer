已接入本地持久信号队列 → 已授权采集库 → Provider 路由与 Publication Gate → 不可变 Report Version → 私有归档/同步/MD/PDF → 重大更正邮件。新增 record/version schema 12、`observer-correction-v1`，旧 schema 1–11 与 Completion 正文不改写。不发现或轮询最近七天报道；自动发现属于 #21。

## 输入与运行

运行配置新增 `"corrections": { "enabled": false }`，默认禁用。显式启用后，`main` 每秒独立处理队列，不依赖当天调度是否启用，也没有12:00截止。启用的 Provider 仍须经过现有地区、账户、执行范围、时限、请求数、共享并发、清理与用量保护。没有真实 Provider、来源、SMTP、凭证读取、Docker 或部署操作。

本地操作者或后续发现器向**实际服务数据库**排队：

```sh
npm run corrections -- --database data/observer.sqlite enqueue data/operator/correction-signal.json
npm run corrections -- --database data/observer.sqlite status correction-example
```

信号只包含来源缓存的精确 `evidenceId + retrievedAtUtc`，不接收原始来源正文、语义核验回执或可直接发布的 Markdown。材料必须已经通过现有采集器存储；处理时从同一运行配置的 collection 数据库读取。缓存缺失、过期、获取时刻改变都会明确 blocked。禁用 schedule 时，修订处理器仍可使用现有合格缓存，但不会为它额外开启日常网络采集。

输入 schema 1 的最小结构如下；标识、候选文字和引用均为示例，不代表已核实事实：

```json
{
  "schemaVersion": 1,
  "signalId": "correction-example",
  "expectedCurrentVersionId": "2026-09-05-v2",
  "affected": [{
    "referenceId": "affected-fact", "versionId": "2026-09-05-v2",
    "storyId": "story-world-affairs", "claimId": "fact"
  }],
  "evidence": [{ "evidenceId": "collected-evidence-id", "retrievedAtUtc": "2026-09-08T06:00:00.000Z" }],
  "finding": {
    "schemaVersion": 2, "id": "error-finding", "eventClusterId": "original-event",
    "edition": "world-affairs", "title": "输入标题不会直接发布",
    "claims": [{ "id": "error", "kind": "fact", "text": "指出原报道事实错误的候选陈述。", "evidenceIds": ["collected-evidence-id"] }]
  },
  "replacement": {
    "schemaVersion": 2, "id": "corrected-story", "eventClusterId": "original-event",
    "edition": "world-affairs", "title": "输入标题不会直接发布",
    "claims": [{ "id": "corrected", "kind": "fact", "text": "经过更正后拟发布的候选陈述。", "evidenceIds": ["collected-evidence-id"] }]
  }
}
```

`finding` 必须只有一个事实 Claim，表示错误/未解错误本身；`replacement` 可为 null。一个信号最多20条受影响陈述、20份材料，限定一个主 Edition；请求最多256KiB。跨栏影响由原正文引用关系进一步扩展。Observer 提供同义的受信进程内 `enqueueCorrection()`、`correctionStatus()`、`processCorrections()`；没有公开排队、编辑或管理路由。

## 证据门与严重度

受影响陈述必须存在于已发布底稿、曾通过 Gate，并且来自当前完整 Canonical 该栏目的真实来源版本；不能仅凭旧版本ID重写已经接受的更正。撤稿后的解除只允许引用该撤稿记录明确列出的原陈述，并重新提供获取时间晚于当前版本发布的有效材料。

每份材料记录实际获取时刻；新更正 Bundle 使用实际核验时刻作为自己的边界，保存 `purpose: correction-review`、接收时间、原Bundle ID/截稿时间和受影响版本/story/claim。旧Bundle与旧报告保持不可变。队列不复制原始来源正文，来源原文继续由既有缓存及有效期控制；新归档只保存当前策略允许的证据元数据。

模型前重新检查当前 Source Policy，剔除模型未获准使用的字段；发布前及事务提交前检查分发、引文元数据与永久归档许可。旧陈述仅作为历史核验上下文，不能充当新事实证据。沿用普通事实的一手或两个独立来源规则、上游独立性、官方声明归因、来源冲突、高风险世界/财经交叉核验、统计时间、研究成熟度与材料安全门。原始社交/GitHub专用来源不能经普通候选接口绕过其专用准入；本票可使用获准的普通来源更正事实陈述，不新增社交样本或项目指标的编辑路径。更正不接受新直接引语。

语义核验增加可选 `revision` 判断：比较原陈述在其原时点是否错误、是否存在有依据的重大未解错误，或只是后来发生的新进展。必须精确返回受影响reference IDs。该判断和finding本身都不能由排队者提供；production使用现有封装的真实语义执行来源检查，测试注入仅用于 `test-fixture`。

| 核验结论 | 发布行为 |
|---|---|
| factual-error，finding与全部replacement Claims通过Gate | 新 correction 版本，只发布已核验变化、理由和证据 |
| unresolved-major-error，finding通过Gate | 新 withdrawal 版本，立即撤回受影响栏目，不等待午前窗口 |
| 重大事实错误已核实但替代内容未全部通过 | 先发布可读撤稿版本，保留未解状态 |
| nonmaterial-transcription 且不属高风险 | minor；无重大更正邮件，缺少合格替代内容时 blocked |
| changed-fact / changed-conclusion / safety-or-financial，或高风险 | major；实际 correction 发布同事务创建 significant-correction 通知 |
| ordinary new-development | deferred-next-edition，不创建版本；保留给下期发现/选题衔接，不声称已经自动选入下一刊 |
| 证据/判断不足、权限或Provider失败 | blocked，固定脱敏原因；不发布未经核实更正 |

`withdrawal` 当前通过归档与sync公开状态，不新增独立撤稿邮件类型。重大**已完成事实更正**复用 #19 的邮件身份；轻微更正、新进展、失败或重复输入不创建重大通知。邮件仍默认禁用，accepted/unknown 不盲重发，accepted不等于实际收件。

## 正文与版本关系

V1采用受影响**栏目**为撤换单位，避免未重新核验的旧标题、分析和跨栏摘要继续依赖错误。受影响栏目整体改为核验后的finding/replacement或撤稿说明；同栏未再次核验的其他故事不恢复，明确 `correction-replaces-affected-edition` 缺口。不受影响的Edition从前版完整Canonical精确继承并保留来源版本；不从Completion只含本次研究的 `record.stories` 重建整刊。总览重新生成栏目状态，不沿用旧事实摘要。

跨栏依赖取自实际Canonical：解析原栏目中的锚点及Markdown片段链接，按完整目标匹配；支持正文的序号 `story-N` 及Completion的 `vN-story-N`，不猜测业务story ID。整栏撤换会移除该栏所有旧锚点，因此指向同栏其他故事的引用也会扩展受影响范围；迭代至无新增依赖，最多遍历六个Edition，避免级联悬空引用留在继承栏目中。没有这些依赖、也未复述原错误陈述的栏目保持原文。

新schema 12的withdrawal是**安全撤稿说明与仍有效内容**，可从latest、精确版本、MD及PDF正常读取；它不是被撤销的旧正文。归档新增 `contentSemantics: safe-withdrawal-notice`，仍兼容原 `status: current | superseded | withdrawn`，并提供 `retracted` 布尔值。旧schema withdrawal保持不可读。

每次接受修订，保守撤销该日期所有先前整刊下载：其总览或跨栏引用可能包含失效结论。原报告字节留在不可变存储，版本索引、取代关系和原因引用仍可查询；旧MD/PDF、精确报告和已签发链接返回410。历史API不静默退回旧正文。已下载文件和已发邮件附件无法被远程擦除；客户端需消费撤回事件隐藏缓存。

新版本读取会校验继承的实际Canonical片段及当前来源权限。内部历史授权只用于确认片段来源，允许检查已撤销的旧整刊；它是同步私有函数，不是HTTP绕过入口。schema12没有套用Completion的v7上限，也不把撤稿旧正文当成可供用户阅读的父版本。

报告INSERT、revision变更、旧版撤回、重大更正通知、队列终态和日期最新状态同一个SQLite事务提交；现有PDF触发器同事务排队，派生MD/PDF及邮件均来自新版本Canonical。旧 `report-published`/同步事件不可改写；新迁移只替换后续报告事件的snapshot触发器，使其包含修订的真实可用栏目。

## 并发、重复与错误解除

单节点默认全队列串行，按持久接收时间和rowid排序；进程内防重入，数据库claim防止多进程同时处理。核验租约61分钟，超过已有最大60分钟路由总时限并预留清理；进程丢失后租约到期可以重新核验。没有外部副作用发生在发布事务前。

排队时固定 `expectedCurrentVersionId`，核验前及 `BEGIN IMMEDIATE` 发布事务内均比较该日期最高版本。陈旧版本或失去claim形成 conflict，不自动rebase。相同signal ID/相同内容幂等；同一组受影响陈述和精确材料版本亦唯一，不同内容冲突。已发布信号、未改事实的no-op或终态blocked不会反复核验、制造新版本或通知；新证据应使用新信号及当前版本。

Completion发布同样新增事务内当前版本比较；修订接受后将当天恢复置closed并更新latest，已有在途Completion不能覆盖它。V1选择更正后停止该日继续补齐，保留缺口；不尝试合并两个核验结果。后续错误解除必须重新核验新材料，再创建下一数字版本，绝不取消旧撤回标记或恢复旧正文。

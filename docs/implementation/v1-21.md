# V1-21：最近七日来源纠错巡查

已实现生产运行时自动巡查：当前已发布陈述 → 精确历史 URL 复读 → 有 TTL 的许可材料 → 既有 Provider 路由生成候选 → #20 独立语义核验、Correction/Withdrawal 及通知队列。默认关闭；本次没有真实来源、模型、SMTP、Docker 或部署操作。

## 范围与预算

上海业务日 D 检查 `[D−7, D)` 七个完整业务日，每个日期只扫描数字版本最高的当前整刊。日期下界包含，上界不包含；当天普通日更形成下一次巡查的范围。按实际 Canonical 栏目及 `sourceVersionId` 追溯 Completion/Correction 继承版本，只给当前仍存在、曾通过 Gate 的陈述建任务。不会从最新 `record.stories` 猜测整刊，也不恢复已移除故事。旧 schema 不支持、当前来源权限/版本来源链失效会记录未覆盖。撤稿说明中仍存在的有效陈述可以巡查，已撤回原故事不会复活。

任务单位是一条已发布 Claim，合并其最多20份引用中的重复来源 URL；这让一个错误不会自动把同故事其他正确事实列为错误。正文中的 Fact、Statement、Analysis、Quotation 均可成为历史比较上下文，新 finding 仍必须只有一个事实 Claim，replacement 不获得直接引语准入。

运行配置新增 `correctionPatrol`：默认 `enabled:false`，`startMinute:360`（06:00）、`deadlineMinute:435`（07:15）、每日80条任务/240次读取、最多3次失败尝试、重试间隔60秒、单任务120秒。配置限定最大300条任务/1000次读取/5次尝试/300秒，截止不得晚于07:15。启用巡查必须同时启用 `corrections`；与普通 `collect`、`schedule.enabled` 独立。

`main` 每秒独立启动巡查，日更冻结、PDF和邮件任务不 await 它。每次网络读取有 Source Policy 超时/响应大小约束，模型使用现有总时限、共享并发、请求/用量预算、地区账户和进程清理保护。巡查任务截止及租约持久化；启动晚于截止也会记录当日未覆盖，重启不会补成“已覆盖”。巡查来源有持久轮询间隔；部分已取得的材料保留精确缓存引用，等待同源下一读取时不会丢失进度。

自动信号使用 `patrol:` 前缀；#20 处理器在07:15前约束到该时刻，07:15–08:30不领取自动信号，08:30后可继续处理排队信号。取消仍经过已有进程清理边界（最多10秒）。手动/其他受信进程的纠错信号保持 #20 行为。任务/信号的阻塞不延迟07:30冻结和08:30可读目标；不声称本次实际验证了真实定时性能。

## 来源与语义边界

`collection.rereadCorrection()` 是内部窄接口，由巡查器从已发布证据元数据提供精确 URL。实际网络复用 `createSourceReader()`，保留同源 HTTPS/443、证书、每次 DNS 检查和地址固定、字节上限与取消机制。每个 hop 必须仍是同一个精确 URL；不会追踪文章里的链接或跳到未报道页面。不携带 feed ETag/Last-Modified；正常 feed 返回304不能替代历史文章复查。

开始读取、DNS/重定向验证、读取完成及模型发送前检查当前 Source Policy。必须允许正文读取、URL/title/content/contentSha256 的采集与存储、有限 TTL、持久记录键、正文模型处理、派生文本及永久归档/引用元数据。策略移除或收紧时缓存被清除、任务留下缺口；不会推断事实已经撤回。`social-discourse`、`github-projects` 专用材料明确 `patrol-specialized-evidence-uncovered`，未绕过专用准入。

200响应的正文首次出现或变化后启动既有 routed research；没有把关键词、更新时间、标题变化、404/410 或本地 JSON 当作事实已错的结论。404/410是 `patrol-source-unavailable`，429是 `rate-limited`。研究 prompt 要求比较原陈述的原时点，区分明确更正/撤回、可靠重大未解冲突、普通后来进展与不确定性。原陈述仅作历史上下文，来源正文仍是不可信数据。

新增可选 `ProduceRequest.correctionResearch`，传入原时间、陈述及事件身份；复用 Codex/Claude runner（没有实际调用 Claude）。候选只允许 `patrol-finding` 与可选 `patrol-replacement`；结构合格后排队，不能发布。#20 再独立调用现有真实语义/Publication Gate，判断原时点错误、影响及替代事实；重大未解错误沿用先撤回，不等待12:00。PDF、私有旧版访问撤销、重大更正邮件仍完全复用 #20 的原事务路径，本票没有另建发布接口。

材料身份由受影响版本/story/claim 与获准的来源URL、策略和正文指纹组成，观察获取时刻单独记录；重启或新一次相同正文读取不会生成新信号。排队与材料身份在同一事务提交。#20 已完成事件不会重发版本和邮件；其既有 `blocked/conflict` 终态在巡查中显示为未覆盖，不冒充可自动解除，来源材料变化后才创建新事件。网络/研究故障按任务预算重试，队列的终态语义保持 #20。

语义判断为普通 `new-development` 时，巡查将同一份仍有效的来源材料交给下一次尚未冻结的普通 Candidate discovery（当前业务日或下一业务日），没有直接采用 replacement 发布。获取时刻保持真实，必须落在下一次普通采集窗内、TTL覆盖其07:30截止；否则明确 `patrol-next-period-material-expired`。同一材料的下一期交接日期持久化，只交接一次；后续正常选题/来源许可/Gate 仍可拒绝它。

## 可见状态与持久内容（#22交接）

服务接口：`observer.processCorrectionPatrol()`、`observer.correctionPatrolStatus(date)`。只读本地命令：

```sh
npm run patrol -- --database data/observer.sqlite status 2026-09-08
```

状态包含七日窗口、截止、总读取数、任务引用、尝试/下一次时间、实际观测时间、材料/信号身份、未覆盖原因及 #20 队列状态/发布版本。`queued` 不代表核验成功；`deferred` 不代表已入选下一刊。没有公开管理路由。

- 报告数据库：`correction_patrol_runs` 保存每日范围/截止/总请求/未覆盖；`correction_patrol_tasks` 保存已发布陈述引用、租约、观察时刻及精确缓存引用；`correction_patrol_materials` 保存获准持久记录身份、队列引用、获取时刻及一次性候选交接日期；`correction_patrol_source_budget` 保存来源下一读取时刻。没有原始来源正文。现有 `correction_signals` 保存不可信 finding/replacement，现有 `routing_runs` 保存路由元数据。
- 采集数据库：新 `correction_source_evidence` 是可变原文缓存，保存精确读取结果、Source Policy身份、实际获取/过期时刻，以及可空的候选业务日。按来源 `retentionHours` 到期删除；当前策略删除/变更时删除旧材料。普通 bundle 仅投影已交接的该期材料，并重新检查当前策略。原始正文不会复制进持久巡查表或报告归档。
- Provider 使用已有 `taskRoot` 隔离运行和清理设施；本票没有新增采样/捕获目录、fixture/matrix/manifest、清理框架或历史清理。#22应连同已有 Agent 任务文件和队列候选文本处理其现有存储义务。

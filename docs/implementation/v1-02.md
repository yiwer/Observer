## Owner configuration and operation

`config/sources.example.v1.json` is the versioned JSON format validated by `SourceConfigurationSchema`/`SourcePolicySchema`. The example is **pending and disabled**. `source.example` is illustrative; it is not a real enabled feed. The self-authored synthetic source is in `tests/fixtures/owner-source`, with an explicit license. The tests' other synthetic source bodies have the same test permission.

After an actual source's rights are reviewed, the Owner supplies its HTTPS feed URL, source identity/type/Edition, review date and basis, field grants, model rights, retention, citation/attribution, distribution and deletion requirements. Set `review.status` to `approved` and `collection.enabled` to `true` only in that Owner-controlled file. Increment the source's `version` for **any** policy edit, including limits or URL. `configurationId` identifies the enclosing configuration release. The Agent-facing interface only accepts `proposeSource`; no method enables a source. File-write access to the Owner configuration is a trusted operator capability and must not be given to Research Agents.

```powershell
npm ci
npm run build
$env:OBSERVER_SOURCE_CONFIG = 'C:\private\observer-sources.v1.json'
$env:OBSERVER_COLLECTION_DATABASE_PATH = 'C:\private\observer-collection.sqlite'
npm run collect
# One bounded polling pass:
npm run collect -- --once
```

The collector process polls sequentially and reports source IDs, counts, outcomes and gaps. It never logs source bodies, exceptions, URLs, authentication headers, or Agent input. Stop with Ctrl+C. It does not open a public port or publish a report. Keep the collection cache separate from `OBSERVER_DATABASE_PATH` and restrict its filesystem permissions to the operator account. The existing `npm start` private report reader remains unchanged.

The public business interface is `createCollection({ databasePath, sources, clock?, read? })`: `collect()` consumes due sources, `bundle(window, stage)` reads a cutoff snapshot for `storage`, `model` or `distribution`, `status()` shows proposals and outcomes, and `close()` closes the cache. `read` is the T1 external-source response seam; production omits it. No source credential support is provided in this generic collector.

## Permission and lifetime semantics

| Control | Observable effect |
|---|---|
| Pending/rejected or collection disabled | No source retrieval; Proposal/Gap, no material in a Bundle |
| `collection.fields` | Only those source fields may be extracted into retained evidence; the upstream feed still arrives transiently as one response |
| `storage.fields`, `retentionHours` | Only that intersection is stored; zero hours or an empty field list leaves no source evidence |
| `retainRecordKeys` | Explicit permission for a hashed source GUID/Atom ID/URL key and bounded HTTP validators; when false, no such keys are retained and cross-poll deduplication is unavailable |
| `model.enabled`, `model.fields` | Model prohibition removes source material from model Bundles and rejects programmatic publication with that source; allowed model fields are projected separately before Runner input |
| `distribution.enabled`, `distribution.fields`, `allowDerivedText` | Programmatic publication refuses a distribution ban and archives only allowed metadata; body text may inform original research without being copied into the archived Evidence Bundle |
| `allowPermanentArchive` | Explicit permission for permanent original report text/allowed quotations and metadata; absent permission rejects publication, regardless of raw cache TTL |
| `citation` | Attribution is applied to source references; explicit `quotations` must occur in permitted research content and fit the per-source Unicode-codepoint limit |
| Removal or higher policy version | Previous cached rows and validators are purged at restart; missing/revoked policy also makes collected archived reports unavailable through `readReport` |

Raw `content` and `contentSha256` are distinct grants. A hash-only policy does not silently save the hashed body. Operational Evidence IDs, Source IDs/types, policy fingerprints and acquisition/expiry times describe Observer's own observations; they are not a grant to retain arbitrary publisher fields. A model-only view can omit citation metadata while the independently derived archive view still includes permitted attribution metadata.

The immutable archive can retain original prose and explicit quotations only under the separate permanent grant. It never embeds raw source `content`. Automated tests cannot classify arbitrary Agent prose as truly original or factual; production publication remains disabled pending later Publication Gate work. There is no claim of complete deletion of already exported material or filesystem forensic erasure. Source families requiring unsupported stream/compliance deletion must remain unapproved: configuration validation rejects `approved` together with `deletion.mode = unsupported`; such sources can only remain pending/rejected proposals.

TTL is enforced on collection, Bundle reads and status reads; the continuously running collector performs these housekeeping passes every second between polls. An offline process cannot purge files while stopped; opening the collector and reading material applies expiry before returning it. Duplicate responses and 304 do not extend raw TTL. Source-policy removal purges the live cache, not backups or immutable historical audit identities.

## Incremental and time semantics

RSS 2.0 and Atom 1.0 are parsed as XML with namespaces, CDATA, Atom alternate links and `xml:base`; relative links use the final permitted feed response URL after redirects. Atom `updated` is not substituted for an unknown original publication date. All supported Unicode languages are retained. UTF-8 is supported; other encodings fail visibly rather than corrupting text. DOCTYPE is rejected, external entities are never resolved, depth is bounded and the complete XML is checked before any item is persisted.

Within an approved source, a permitted GUID/Atom ID falls back to its direct URL as the record key. Content/metadata changes preserve the Evidence ID and first discovery time, update retrieval time and replace that cached revision. The material's policy fingerprint and optional content hash distinguish the revision. The cache holds the latest revision, not a historical archive capable of reconstructing all previous cutoffs. A later revision cannot be backdated into an earlier cutoff; an already-created Bundle is an independent value snapshot.

First discovery is when the feed response becomes available, and body retrieval is when that body actually returns, not when polling started. Invalid or unzoned publication timestamps retain the allowed raw string with normalized time `null`; no event time is inferred. A source body obtained after cutoff is excluded. `poll-not-due`, `no-change`, `not-modified`, changed/added and duplicate counts are normal outcomes. Timeout, 429, policy exclusion and unavailable evidence are gaps, never assertions that a region has no news. Each unresolved source failure persists across skipped polls and process restart until an observed successful poll clears it.

ETag and Last-Modified conditional requests survive restart when validator retention is authorized. 429 respects Retry-After seconds or HTTP date with a 24-hour cap; otherwise the configured poll interval applies. There are no immediate retry loops. The example uses a 300-second poll, a 10-second request deadline, 256 KiB per response, 100 items and at most 3 redirect hops. Runtime maxima are 1 MiB, 1,000 items, 30 seconds per request, 5 hops and 100 configured sources. These are bounded implementation defaults, not production capacity qualification.

## Network evidence and limits

Production uses Node 24.18.0 `https.request`, normal certificate verification and the original hostname/SNI. It ignores proxy-environment behavior by using a fresh non-pooled request. Every hop must remain HTTPS on port 443 and the reviewed source origin. IP-literal, local-name and credential-bearing targets are denied. Every resolved address must classify as public unicast, then the request's lookup is pinned to the selected address; DNS is checked again on redirects. Bytes are counted while streaming, including absent/false Content-Length; compressed bodies, invalid UTF-8, oversized headers and stalled responses fail closed. No HTML, script, feed instruction or candidate code is executed.

Primary technical evidence: [Node 24.18 HTTPS](https://nodejs.org/download/release/v24.18.0/docs/api/https.html), [Node 24.18 HTTP](https://nodejs.org/download/release/v24.18.0/docs/api/http.html), [Atom RFC 4287](https://www.rfc-editor.org/rfc/rfc4287), [saxes source and entity behavior](https://github.com/lddubeau/saxes), [ipaddr.js public classification interface](https://github.com/whitequark/ipaddr.js). Locked additions are saxes **6.0.0** and ipaddr.js **2.2.0**. Saxes is archived upstream; its non-fetching XML parser is bounded here, but future vulnerability/maintenance review remains necessary. npm installation reported zero known vulnerabilities; that is not a security proof.

Socket tests use **real local HTTP sockets plus injected DNS/transport**. They cover private/mixed DNS results, rebinding on redirects, encoded IP literals, malicious/cross-origin redirects, loops, streamed/announced oversize bodies, invalid UTF-8, compression, stalls and DOCTYPE/XXE, with valid sources still producing usable Bundles. They do **not** qualify production HTTPS/TLS, a live external publisher or that publisher's license.

## Verification ledger

T1 red→green slices were observed for: pending-source exclusion; RSS material and times; incremental restart/Atom updates; independent storage/model grants and expiry; timeout/429/304; public Runner/report permission enforcement; original research with separate citation metadata; configuration revocation and conditional GET; Atom relative links and input limits; explicit quotations/read revocation; built continuous collector; acquisition across cutoff; invalid source calendar dates. The network matrix also broadens the same source I/O seam without relying on private-method call counts.

Final commands are `npm run check` (static TypeScript check, build and every test) and `npm run smoke` (build, original private HTTP process tests and the continuous collector process test). Exact terminal counts and frozen commit are supplied in the ticket handoff. This is automated/static and local socket/process evidence only. Real source acquisition, live model behavior, manual rights review, production publishing and deployment are **not verified**.

Independent review of provisional `8cd9e726bf1927b1f31e7199f15b0943c053573a` found one Standards hard issue (quotation allowance was applied per Evidence rather than per Source) and two Spec issues (failure gaps disappeared on skipped polls; redirected feeds used the original URL for relative links). All three received public-seam regressions that first failed: a missing `citation-limit` rejection; an absent `timeout` gap; and zero collected items when the correct redirected body should succeed. The fixes sum quotations across the source, persist unresolved source gaps, and propagate the vetted final response URL. The Standards suggestion to reduce duplicated stage-projection code remains a nonblocking maintenance judgment.

Root's separate acceptance probe on `689ffaf13ae2b3f3a8d4302d08584d11b38fbe62` found that unsupported deletion obligations could still be marked approved. A public configuration-admission regression first failed because no exception occurred; validation now rejects this combination before opening the cache or retrieving material, while pending proposals remain available. This closes admission only and does not implement a social/compliance deletion protocol.
